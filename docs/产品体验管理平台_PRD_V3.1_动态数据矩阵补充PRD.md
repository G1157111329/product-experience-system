## 0.1 本次补充最重要的边界说明

### 0.1.1 V3.1 文档中“已写到”不等于当前系统“已实现”

V3.1 中已包含以下相关设计表达：

- 报告动态结果区可展示“功能/食谱效果、指标结果、对比矩阵、五感/操作”等内容。
- 报告矩阵具有固定上下文、筛选差异/异常、单元格展开、就地证据、指标公式面板、报告快照等设计原则。
- 任务侧已经存在功能/食谱效果、五感/操作、指标测量、问题、证据等业务对象与录入链路。

但以上内容不能被理解为“用户可在任务中自行设计一份动态数据矩阵，并自行决定字段、单位、计算规则和结构”的能力已经开发完成。

### 0.1.2 当前已开发能力基线（本需求的实际改造起点）

当前平台已经实现并继续保留：

| 已实现模块 | 当前定位 | 本次是否重做 | 与动态数据矩阵的关系 |
|---|---|---:|---|
| 对比矩阵 | 已有对比型阅读/呈现能力，用于查看既有对比结果 | 否 | 保持原能力；动态数据矩阵可在报告中形成新的矩阵投影，但不得覆盖或替换现有对比矩阵数据。 |
| 五感体验 | 已有体验任务录入能力 | 否 | 保持原入口和数据；动态数据矩阵可通过问题、证据、记录项与其并行存在，不复制其事实。 |
| 功能效果 | 已有体验任务录入能力 | 否 | 保持原入口和数据；矩阵行可关联功能效果记录，但不能自动复制或双写。 |
| 问题、证据、整改、复测 | 已有主业务闭环 | 否 | 动态数据矩阵必须复用该闭环。 |
| 报告阅读与快照 | 已有或按 V3.1 既定主线实施 | 不重做主流程 | 新增“数据矩阵投影”作为动态结果区的一种只读结果组件。 |

### 0.1.3 本次新增能力的准确名称

本 PRD 新增的能力统一命名为：

> **动态数据矩阵（Dynamic Task Matrix）**

其定义为：

> 在单个体验任务中，由有权限的业务用户针对本次测试自行设计一次矩阵结构、字段、分区、单位、结果规则、证据槽位、问题关联槽位与同行计算字段，并对其进行结构化录入、校验、问题闭环和报告投影的能力。

### 0.1.4 必须避免的错误理解

| 错误理解 | 正确理解 |
|---|---|
| “现有对比矩阵就是数据矩阵，所以只需加几列。” | 错。现有对比矩阵是既有呈现能力；动态数据矩阵是新的任务侧设计、录入、计算、审计和快照能力。 |
| “给现有五感/功能效果页面加个 Excel 表就行。” | 错。动态数据矩阵必须有稳定的数据模型、字段 ID、公式版本、证据/问题映射、并发控制与报告快照。 |
| “数据矩阵要替代五感和功能效果。” | 错。三者并存。五感与功能效果继续承载既有结构化体验记录；矩阵用于高密度、多维、多字段记录。 |
| “Excel 中有的内容都要无损搬到网页。” | 错。只保留业务结构、字段、数值、公式、证据和结论；不实现自由样式、合并单元格和 A1 公式。 |
| “V3.1 说过指标和矩阵，就表示该模块已经在当前代码里。” | 错。本文将动态数据矩阵定义为明确的新增开发模块。 |

## 0.2 业务背景与需求来源

当前产品体验工作以 Excel 为主要载体。Excel 对现场快速录入、多行多列比较、公式查看、局部备注和图片贴近数据有明显优势；但其内容难被平台识别为稳定业务对象，导致：

1. 同一测试事实同时散落在功能效果、五感体验、Excel 和报告中。
2. 图片在单元格附近，但系统无法确定其究竟属于哪一行、哪一项测试、哪一个问题。
3. 公式依赖 A1 坐标，插入行/列后容易失效，且无法稳定进入报告、导出、审计和复测链路。
4. 多人编辑时容易覆盖数据，无法对字段级、行级修改做追溯。
5. 报告需要重新组织 Excel 内容，导致重复录入或人工抄写。
6. 手机现场拍照、补数、问题创建难以与原始矩阵结构保持一致。

本次新增模块的目标不是做一个网页版 Excel，而是将 Excel 中真正有业务价值的结构能力转化为任务事实：

```text
用户单次设计结构
  -> 录入行与字段值
  -> 服务端计算与校验
  -> 绑定证据和问题
  -> 任务审核
  -> 报告只读投影
  -> 发布快照冻结
```

# 1. 产品目标、非目标与成功指标

## 1.1 产品目标

| 编号 | 目标 |
|---|---|
| G-MX-01 | 体验人员可在当前任务内自行设计本次矩阵，不依赖管理员预置“耗时、重量、评分、出汁率”等业务字段。 |
| G-MX-02 | 用户可定义自由分组名称、行名称、字段分区、字段类型、单位、结果状态、证据和问题槽位。 |
| G-MX-03 | 用户可创建受控的同行计算字段，系统可稳定计算、显示失败原因、留存公式版本。 |
| G-MX-04 | 矩阵中的数值、图片、问题和结论都可回到任务、记录项、证据、问题主档与复测链路。 |
| G-MX-05 | 已有对比矩阵、五感体验、功能效果不会被重构、覆盖或双写。 |
| G-MX-06 | 报告可只读展示矩阵结果，已发布报告快照不因任务后续修改而变化。 |
| G-MX-07 | 手机端支持完整的现场设计、录入、拍照、问题创建、校验修复；不强行压缩横向大表。 |

## 1.2 非目标

| 非目标 | 明确边界 |
|---|---|
| 任意 Excel 无损还原 | 不解析合并单元格、字号、字体、颜色、图片像素位置、A1 公式。 |
| 通用电子表格 | 不实现工作簿、工作表、宏、脚本、命名区域、数据透视表。 |
| 用户自由跨行公式 | P0 不允许引用“第 3 行”“第 9 行”“某分组平均值”。 |
| 公式脚本化 | 不执行 JavaScript、SQL、HTML、宏、Python、远程函数或第三方表达式。 |
| 替代既有模块 | 不替代对比矩阵、五感体验、功能效果。 |
| 报告编辑事实 | 报告页只读，不允许编辑矩阵事实。 |
| 自动创建/关闭问题 | 异常仅提示和阻断；Issue 必须由用户确认创建或关联。 |
| 自动得出“最优产品” | 只有字段数据和差异；除非未来另行建立可比性与推荐规则。 |
| P0 历史 Excel 导入 | P0 仅保存附件；受控模板导入进入 P1/P2。 |

## 1.3 成功指标

| 类型 | 指标 | P0 目标 |
|---|---|---|
| 设计效率 | 首次设计一份 10 字段以内矩阵的中位耗时 | ≤ 8 分钟 |
| 录入效率 | 完成 1 条 8 字段矩阵行的中位耗时 | 比 Excel 录入降低 20% 或不高于 Excel 基线 |
| 录入完整性 | 矩阵任务提交时必填字段、关键证据、问题关联完整率 | ≥ 95% |
| 公式稳定性 | 同行公式计算成功率 | ≥ 99.5% |
| 可追溯性 | 矩阵中的数值/证据/问题可回到来源任务的比例 | 100% |
| 报告一致性 | 发布快照与当次矩阵投影一致率 | 100% |
| 手机可用性 | 现场手机完成一条行记录及拍照的成功率 | ≥ 95% |
| 数据安全 | 并发冲突导致无提示覆盖的比例 | 0 |

# 2. 与既有模块的边界、复用与跳转

## 2.1 总体关系

```text
既有模块（不改造事实）
  ├─ 功能效果
  ├─ 五感体验
  ├─ 对比矩阵
  ├─ 问题中心
  └─ 证据中心

新增模块（本 PRD）
  └─ 动态数据矩阵
       ├─ 用户单次设计
       ├─ 行级结构化录入
       ├─ 受控同行公式
       ├─ 证据与问题绑定
       ├─ 任务提交校验
       └─ 报告只读投影
```

## 2.2 功能效果与动态数据矩阵

| 项目 | 功能效果 | 动态数据矩阵 |
|---|---|---|
| 适用场景 | 单项功能、食谱、步骤、效果判断 | 多维记录、多对象/场景/批次、多字段/指标比较 |
| 结构 | 平台既有固定业务结构 | 用户按本次任务单次设计 |
| 核心录入 | 效果、说明、步骤、证据、问题 | 自定义字段、计算、证据、问题、分组/行 |
| 是否替代 | 否 | 否 |
| 关联方式 | 可从矩阵行关联一个或多个功能效果 RecordItem | 可在矩阵行中保留 `linked_record_item_ids`，但不自动复制内容 |

### 强制规则

- 矩阵行可关联功能效果记录，但默认不自动创建功能效果记录。
- 若用户从功能效果页发起“新增关联矩阵行”，系统只预填任务、对象、测试条件等公共上下文，不复制效果结论。
- 功能效果的证据与矩阵证据可以关联同一 Evidence，但必须通过独立 `evidence_links` 显式绑定，不得复制文件。

## 2.3 五感体验与动态数据矩阵

| 项目 | 五感体验 | 动态数据矩阵 |
|---|---|---|
| 适用场景 | 视觉、听觉、触觉、嗅觉、味觉、清洁、噪音等既有体验记录 | 任意用户自定义维度与字段的批量/对比记录 |
| 数据结构 | 平台既有字段和记录方式 | 用户单次设计字段与分区 |
| 关系 | 保持独立事实来源 | 可用问题、证据、任务上下文互相跳转 |

### 强制规则

- 不将五感体验字段自动映射到矩阵字段。
- 不将矩阵字段自动写入五感体验。
- 需要在报告中并列展示时，报告只做阅读层聚合，不生成新的事实副本。

## 2.4 既有对比矩阵与动态数据矩阵

| 项目 | 既有对比矩阵 | 动态数据矩阵 |
|---|---|---|
| 当前状态 | 已开发能力，继续保留 | 新增开发模块 |
| 核心用途 | 对已有业务对象进行对比展示/阅读 | 在任务中按本次需求定义结构并录入事实 |
| 数据来源 | 当前既有模块的数据投影 | TaskMatrix、字段值、MetricRecord、Evidence、IssueOccurrence |
| 编辑能力 | 维持当前实现 | 仅任务侧编辑，报告只读 |
| 是否迁移旧数据 | 否 | 不迁移、不反向转换 |

### 上线期间的前台命名

为避免用户将两类能力混淆：

| 页面 | 建议名称 |
|---|---|
| 新任务工作台入口 | `数据矩阵（自定义）` |
| 既有报告阅读区 | 保持现有 `对比矩阵` 名称 |
| 报告中来自新模块的区块 | `数据矩阵`，副标题显示矩阵名称 |

P1 可根据用户使用习惯评估是否去掉“自定义”后缀；P0 不建议将两个模块使用同一入口名称。

## 2.5 与问题、证据、整改、复测的关系

| 既有对象 | 动态数据矩阵要求 |
|---|---|
| Issue | 用户可从矩阵问题槽位创建或关联既有 Issue。 |
| IssueOccurrence | 必须记录当前矩阵、分组、行、字段、字段值、证据与上下文。 |
| Evidence | 必须使用既有上传、扫描、转码、权限、审计机制。 |
| RectificationAction | 不在矩阵中创建；从问题详情进入整改链路。 |
| Verification | 不在矩阵中直接关闭问题；复测仍通过任务/问题主链路。 |
| ReportSnapshot | 发布时冻结矩阵设计、值、公式、证据和问题引用。 |

# 3. 核心概念、对象与数据模型

## 3.1 概念定义

| 名称 | 定义 |
|---|---|
| TaskMatrix | 某体验任务下的一份动态数据矩阵实例。 |
| MatrixDesignVersion | 某矩阵一次确认后的结构版本。 |
| MatrixAxis | 用于组织分组和行的结构槽位。 |
| MatrixSection | 用户定义的字段分区，例如“测量记录”“结果判断”“证据与问题”。 |
| MatrixFieldDefinition | 用户自定义字段的稳定定义。 |
| MatrixGroup | 一级分组；业务语义自由。 |
| MatrixRow | 最小记录单元；一行对应一条 `RecordItem`。 |
| MatrixFieldValue | 文本、选择、日期、布尔等非数值字段值。 |
| MatrixFormulaDefinition | 计算字段的受控公式定义。 |
| MatrixCalculationRun | 服务端执行计算的审计记录。 |
| MatrixNarrative | 分组或矩阵级文字小结。 |
| MatrixReportProjection | 供报告只读展示的矩阵投影。 |

## 3.2 结构轴：允许业务语义自由，不允许数据结构失控

P0 使用固定槽位承载自由语义。

| 结构槽位 | 是否必填 | 用户可输入内容 | 示例 |
|---|---:|---|---|
| `group_axis` | 否 | 一级分组名称 | 产品、场景、食材、用户类型、批次 |
| `row_axis` | 是 | 行名称 | 口径、型号、档位、测试轮次、对象 |
| `sub_row_axis` | 否 | 次级行名称 | 原料批次、配件、环境、模式 |

### 规则

1. 用户可自由输入“产品”“场景”“食材”等显示名称；平台不强制分类。
2. 系统只约束结构槽位，不允许用户无限追加第四、第五层结构。
3. `row_axis` 必须启用，因为一条矩阵记录必须有明确行归属。
4. 同一父分组下，不允许完全相同的 `row_axis + sub_row_axis` 组合。
5. 分组、行的显示名称可在未录入数据时修改；录入后修改名称保留审计。
6. 已有事实数据的分组或行不得物理删除，只能归档。

## 3.5 设计版本：`matrix_design_versions`

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | UUID | 主键。 |
| `matrix_id` | UUID | 所属矩阵。 |
| `version_no` | INT | 从 1 起递增。 |
| `status` | ENUM | `draft / confirmed / superseded / retired`。 |
| `design_hash` | VARCHAR(128) | 对完整结构做哈希，用于快照核验。 |
| `created_by` | UUID | 创建人。 |
| `confirmed_by` | UUID | 确认人。 |
| `confirmed_at` | TIMESTAMP | 确认时间。 |
| `change_type` | ENUM | `initial / safe_addition / safe_presentation_change`。 |
| `change_reason` | TEXT | 非初始版本必填。 |

### 设计版本约束

- 已确认版本不可原地改写。
- 允许新增可选字段、调整显示名称、排序等安全修改，并生成新设计版本。
- 改变字段数据类型、改变已使用公式逻辑、改变单位语义、轴位互换、删除已使用字段等属于破坏性变更。
- 破坏性变更不得生成同矩阵新版本；必须创建一个新的 `TaskMatrix` 实例，避免混淆历史事实语义。

## 3.6 分区、字段与字段类型

### 3.6.1 字段分区 `matrix_sections`

| 字段 | 规则 |
|---|---|
| `name` | 用户自由输入，同 Scope 内不可重名。 |
| `scope` | `row / group / matrix`。 |
| `sort_order` | 用户可调整。 |
| `description` | 可选。 |
| `is_collapsible` | 是否允许折叠。 |
| `default_expanded` | 默认展开状态。 |

## 4.2 矩阵状态机

```text
designing
  -> active
  -> review_locked
  -> completed
  -> archived

review_locked -> active      审核退回
completed -> active          任务重新打开

designing / active -> archived
```

| 状态 | 说明 | 允许操作 |
|---|---|---|
| `designing` | 矩阵结构尚未确认 | 编辑结构、保存草稿、预览。 |
| `active` | 可以录入事实 | 新增分组/行、编辑字段、上传证据、创建问题、执行安全结构增量。 |
| `review_locked` | 任务已提交审核 | 只读。 |
| `completed` | 任务完成 | 只读；任务 reopened 后恢复 active。 |
| `archived` | 废弃但必须可追溯 | 只读。 |

## 4.3 设计修改规则

### 未录入事实前

用户可自由修改：

- 轴名称。
- 分区名称与顺序。
- 字段名称、类型、单位、选项、公式、校验。
- 证据与问题槽位。

### 已录入事实后允许的安全修改

| 修改 | 行为 |
|---|---|
| 修改字段显示名称 | 生成安全设计版本，字段 ID 不变。 |
| 调整分区或字段显示顺序 | 生成安全设计版本。 |
| 新增可选字段 | 生成安全设计版本；历史行值为空。 |
| 新增计算字段 | 生成安全设计版本；对现有行执行计算。 |
| 新增可选证据/问题槽位 | 生成安全设计版本。 |
| 隐藏字段 | 字段归档；历史值可读、可导出、可快照。 |

### 已录入事实后禁止直接修改的破坏性变更

| 修改 | 系统行为 |
|---|---|
| 数值改文本、文本改单选、单选改多选 | 禁止；需新建矩阵副本。 |
| 更改已使用字段的单位语义 | 禁止；需新建矩阵副本。 |
| 更改已使用计算字段的核心公式 | 禁止；需新建矩阵副本。 |
| 删除已存在值的字段 | 禁止；仅允许归档。 |
| 交换分组轴和行轴 | 禁止；需新建矩阵副本。 |
| 普通字段改证据槽位或问题槽位 | 禁止；需新建矩阵副本。 |

### 破坏性变更提示

```text
你正在修改已录入数据的矩阵结构。

该修改会改变历史数据的业务含义，不能直接覆盖当前矩阵。
系统将创建一份新的矩阵实例，仅复制结构，不复制事实数据、证据和问题。

[取消] [创建新矩阵副本]
```

```text
任务信息条
```

```text
可创建一份由本次任务自行设计的动态数据矩阵。

```

### 入口权限

- 执行人、任务负责人、管理员可见“新建数据矩阵”。
- 审核人仅在任务处于审核退回且有编辑授权时可跳转查看，不默认可创建。
- 没有任务权限的用户访问 URL 返回 403，页面不得泄露矩阵名称、行数、问题数量、产品信息。

## 5.2 矩阵列表页

```text
数据矩阵（自定义）                              [新建数据矩阵]

原汁效果对比矩阵
设计 V1 | 18 条记录 | 3 条异常 | 2 个问题 | 最后保存 10:32
[进入录入] [查看小结] [归档]

清洁效率测试矩阵

[进入录入] [查看小结] [归档]
```

### 列表规则

1. 一个任务最多 10 份活跃矩阵。
2. 已归档矩阵默认隐藏，可通过“显示已归档”查看。
3. 卡片显示：名称、状态、当前设计版本、活跃行数、异常行数、Issue 数、最后保存时间。
4. 点击“进入录入”进入矩阵详情。
5. 从报告跳转时，必须保留 `matrixId`、`groupId`、`rowId`、`fieldId` 焦点。

## 5.3 矩阵设计器

不使用右侧抽屉。采用全页步骤式设计器。

```text
矩阵名称 / 保存状态 / 设计版本

[1 基础结构] [2 分区与字段] [3 公式] [4 规则与联动] [5 预览与确认]

当前步骤内容

[上一步] [保存草稿] [下一步]
```

### 5.3.1 第一步：基础结构

| 字段 | 必填 | 规则 |
|---|---:|---|
| 矩阵名称 | 是 | 1–100 字符；任务内不可重名。 |
| 矩阵说明 | 否 | 最多 500 字符。 |
| 启用一级分组 | 是 | 默认启用；可关闭。 |
| 一级分组名称 | 启用时必填 | 用户自由输入。 |
| 行名称 | 是 | 用户自由输入。 |
| 次级行名称 | 否 | 用户自由输入。 |
| 可比性状态 | 是 | 默认 `pending`；单对象矩阵可选择 `not_applicable`。 |
| 可比性说明 | 条件必填 | 多对象/多行比较在提交审核前必填。 |

### 5.3.2 第二步：字段分区与字段

用户可创建任意业务命名的分区，例如：

```text
测量记录
过程观察
结果判断
证据与问题
```

但系统不得预置以上分区。

#### 分区规则

- 至少一个 `row` Scope 分区。
- 同 Scope 分区名称不可重复。
- 分区可排序，不支持无限嵌套。
- 分区删除前必须清空或移动字段；有历史数据的字段只能归档。

#### 字段配置组件

| 组件 | 必须支持 |
|---|---|
| 字段名称输入框 | 最大 100 字符，去除首尾空格。 |
| 字段类型选择器 | 仅显示当前 Scope 可用类型。 |
| 必填设置 | 可选、必填、条件必填。 |
| 单位输入 | 数值/百分比/时长可设置，最多 30 字符。 |
| 小数位选择 | 0–6 位。 |
| 合理范围 | 最小值、最大值、超限为预警或阻断。 |
| 选项编辑器 | 单选、多选字段可新增、排序、编辑选项。 |
| 展示位置 | 桌面矩阵、手机卡片、报告投影开关。 |
| 报告优先级 | 主字段、次字段、隐藏。 |
| 允许未测试/不适用 | 按字段开启或关闭。 |

### 5.3.3 第三步：公式

用户可为当前矩阵定义计算字段，但只允许同行引用。

```text
字段名称：[出品率]
结果格式：[百分比]
小数位：[1]

公式：
[成品重量 ▼] [÷ ▼] [原料重量 ▼]

表达式预览：
{成品重量} / {原料重量}

异常策略：
☑ 输入为空时显示“待补充”
☑ 分母为 0 时显示“无法计算”
□ 计算失败时阻断任务提交
```

### 5.3.4 第四步：证据、问题与结果映射

#### 证据槽位

| 配置项 | 规则 |
|---|---|
| 槽位名称 | 用户自由输入。 |
| 媒体类型 | 图片、视频、附件。 |
| 最大数量 | P0 单槽位最多 10 个。 |
| 是否必填 | 可配置。 |
| 是否关键证据 | 可配置。 |
| 条件必填规则 | 可基于本行单选/布尔字段配置。 |
| 上传说明 | 默认允许填写。 |

#### 问题槽位

| 配置项 | 规则 |
|---|---|
| 槽位名称 | 用户自由输入。 |
| 允许新建 Issue | 默认允许。 |
| 允许关联已有 Issue | 默认允许。 |
| 条件必填规则 | 可基于失败状态、异常字段、布尔字段配置。 |
| 默认上下文 | 自动带入矩阵、分组、行、字段、值、测试条件、证据。 |

#### 结果状态映射

系统不预置“达标/不达标”。用户可从本次设计的单选字段中选择一个作为“结果状态字段”。

```text
字段：体验结果

符合预期       -> pass
待进一步观察   -> observe
未符合预期     -> fail
不适用         -> not_applicable
```

规则：

- 一个矩阵最多指定一个行级结果状态字段。
- 未指定结果状态字段时，系统不自动判断当前行是否失败。
- 映射为 `fail` 时，任务提交前必须关联 Issue、填写豁免或标记测试无效。

### 5.3.5 第五步：预览与确认

必须提供：

- 桌面矩阵预览。
- 平板预览。
- 手机卡片预览。
- 设计错误与预警汇总。
- “确认并开始录入”按钮。

确认后：

1. 生成 `MatrixDesignVersion v1`。
2. 锁定初始设计版本。
3. 将 Matrix 状态改为 `active`。
4. 记录确认人、确认时间、设计哈希。

4. 媒体和问题字段显示状态/数量，不在一个单元格内堆叠大量缩略图。
5. 点击媒体进入全屏预览；关闭后返回原行位置。
6. 点击问题进入问题详情页；不使用右侧抽屉。
7. 行展开区用于编辑长文本、查看证据、关联问题、查看计算详情。
8. 使用虚拟列表和分段加载，禁止一次性渲染全部图片或全部行。
9. 已归档行默认隐藏；有权限用户可切换查看。

### 新增分组

| 字段 | 必填 | 规则 |
|---|---:|---|
| 分组名称 | 是 | 1–100 字符；同级不可重复。 |
| 分组说明 | 否 | 最多 500 字符。 |

### 新增行

| 字段 | 必填 | 规则 |
|---|---:|---|
| 行值 | 是 | 1–100 字符。 |
| 次级行值 | 否 | 1–100 字符。 |
| 所属分组 | 启用分组时必填 | 选择现有分组或同步新增。 |

### 行创建后的后台动作

1. 创建 `MatrixRow`。
2. 创建一条 `RecordItem`，`record_item_type=matrix_row`。
3. 预生成必要的空字段投影，但不无意义生成全部 MetricRecord。
4. 写入审计。
5. 返回新行 ID、RecordItem ID、版本号。

## 5.6 桌面端批量粘贴

### 支持范围

- 仅桌面端。
- 仅支持数值、百分比、时长、文本、单选字段。
- 仅支持从一个已选起始单元格向右、向下粘贴制表符分隔数据。
- 不支持公式字段、媒体槽位、Issue 槽位。
- 不自动新增字段。
- 默认不自动新增分组。

### 处理流程

```text

  -> Ctrl/Cmd + V
  -> 前端解析剪贴板

  -> 服务端全量校验
  -> 全部有效：事务写入
  -> 任一无效：整体拒绝，不部分写入
  -> 触发受影响公式重算
```

### 错误示例

```text

```

# 6. 公式能力与计算规则

## 6.1 公式原则

1. 用户可以创建计算字段，但不能输入 Excel 坐标引用。
2. 公式只允许引用同一矩阵、同一行、同一设计版本内的数值、百分比、时长、布尔字段。
3. 前端显示字段名称；服务端保存稳定字段 ID。
4. 服务端是计算结果权威来源。
5. 公式不得修改其他字段、创建 Issue、改变任务状态或触发通知。

## 6.2 支持语法

### 允许

```text
+  -  *  /  ( )

ROUND(value, digits)
ABS(value)
MIN(value1, value2, ...)
MAX(value1, value2, ...)
IF(condition, value_if_true, value_if_false)

>  >=  <  <=  ==  !=
```

### 禁止

```text
=G4/G9
=SUM(A1:A10)
=VLOOKUP(...)
=INDIRECT(...)
=OFFSET(...)
=IMPORTXML(...)
=HTTP(...)
=eval(...)
任意脚本、宏、SQL、HTML、JavaScript
```

## 6.3 公式存储示例

```json
{
  "field_id": "mf_yield",
  "formula_version": 1,
  "display_expression": "{成品重量} / {原料重量}",
  "normalized_expression": "DIV(FIELD(mf_output_weight), FIELD(mf_input_weight))",
  "return_type": "percentage",
  "decimal_places": 1,
  "dependencies": ["mf_output_weight", "mf_input_weight"]
}
```

## 6.4 公式校验

| 校验 | 结果 |
|---|---|
| 未引用可计算字段 | 阻止保存。 |
| 引用不存在字段 | 阻止保存。 |
| 引用文本、图片、视频、Issue 字段 | 阻止保存。 |
| 自引用或循环依赖 | 阻止保存。 |
| 使用未在白名单内的函数 | 阻止保存。 |
| 公式返回类型与字段类型不匹配 | 阻止保存。 |
| 输入为空 | 允许保存；运行时显示待补充。 |
| 分母为 0 | 允许保存；运行时显示计算失败。 |

## 6.5 计算执行流程

```text
用户保存手工字段
  -> 服务端校验输入
  -> 保存字段值
  -> 读取受影响计算字段依赖图
  -> 按拓扑顺序执行公式
  -> 写入 MetricRecord
  -> 写入 MatrixCalculationRun
  -> 返回最新行投影与计算状态
```

## 6.6 计算结果状态

| 状态 | 前台文案 |
|---|---|
| `success` | 正常显示计算结果。 |
| `pending_input` | `待补充：缺少“字段名称”`。 |
| `division_by_zero` | `无法计算：除数不能为 0。` |
| `type_error` | `无法计算：字段类型不匹配。` |
| `runtime_error` | `计算暂时失败，系统将自动重试。` |
| `formula_invalid` | `当前公式不可用，请联系矩阵设计人。` |

# 7. 证据、问题与既有业务闭环

## 7.1 证据槽位

所有媒体必须创建既有 `Evidence`，并通过 `evidence_links` 显式绑定到：

- MatrixRow。
- RecordItem。
- 指定 MatrixFieldDefinition。
- 需要时绑定 IssueOccurrence。

### 上传流程

```text
选择文件 / 拍照
  -> 本地格式、大小、数量校验
  -> 短期签名 URL 直传
  -> 病毒扫描
  -> 图片缩略图或视频转码
  -> Evidence 可用
  -> 绑定当前矩阵行与证据槽位
```

### 媒体规则

| 规则 | 说明 |
|---|---|
| 上传中媒体 | 状态为 `processing`，不可作为发布关键证据。 |
| 扫描失败媒体 | 标记 `failed`，不允许用于提交审核。 |
| 已发布快照引用媒体 | 不可物理删除，只能标记不可用并说明原因。 |
| 单槽位上限 | P0 默认最多 10 个。 |
| 重复文件 | 可上传，但系统提示可能重复；P0 不强制去重。 |

## 7.2 问题创建与关联

矩阵中的问题槽位点击“创建问题”时，自动预填：

- Task。
- TaskMatrix。
- MatrixDesignVersion。
- MatrixGroup。
- MatrixRow。
- 关联 RecordItem。
- 当前字段与字段值。
- 当前分组/行名称。
- 已绑定证据。
- 当前测试对象、阶段、测试条件。
- 创建人、创建时间。

### 强制规则

- 系统不自动创建正式 Issue。
- 用户必须确认问题现象、严重度、影响范围等既有必填字段。
- 关联已有 Issue 时，必须创建新的 IssueOccurrence，不得仅在前端显示链接。
- 创建后，矩阵行即时显示问题数量、严重度与当前状态摘要。

## 7.3 失败、豁免与测试无效

如果用户配置结果状态字段且某行映射为 `fail`，提交审核前必须满足其一：

1. 至少关联一条 IssueOccurrence。
2. 填写“无需建问题”豁免说明，并由任务负责人确认。
3. 标记“测试无效”，并填写无效原因。

# 9. 自动保存、离线、并发与冲突

## 9.1 自动保存

| 场景 | 行为 |
|---|---|
| 输入停止 800ms | 自动保存。 |
| 切换字段 | 立即保存。 |
| 点击返回 | 检查待保存变更。 |
| 提交审核 | 等待待保存请求完成后再校验。 |
| 成功 | 显示“已保存”。 |
| 进行中 | 显示“保存中”。 |
| 失败 | 显示“保存失败，可重试”。 |

## 9.2 离线规则

### 可以离线暂存

- 文本。
- 数值。
- 时长。
- 单选、多选。
- 布尔。
- 日期时间。
- 新增分组、行的本地草稿。

### 媒体离线边界

| 场景 | 行为 |
|---|---|
| 已拍摄但未上传 | 尝试写入浏览器本地临时队列。 |
| 本地容量不足 | 提示文件未保存到服务器，要求恢复网络后重新上传。 |
| 用户关闭页面 | 不承诺浏览器一定保留未上传原文件。 |
| 上传未完成 | 不得显示为“已保存证据”。 |
| 上传完成 | 创建 Evidence 并绑定业务对象。 |

## 9.3 并发与乐观锁

### 行级并发

- 每个 MatrixRow 有 `version`。
- 每次字段更新需携带 `row_version` 或 `If-Match`。
- 版本不一致时服务端返回 `409 Conflict`。
- 前端不得静默覆盖。

### 设计级并发

- 每次设计修改需携带 `design_version`。
- 两人并发修改结构，先保存成功者为准。
- 后保存者收到 409 并可查看差异、重新加载或复制草稿。

### 冲突界面

```text
该记录已被其他用户更新。

服务器版本：
成品重量：558.7 g
更新人：张三
更新时间：10:32:11

我的版本：
成品重量：560 g

[采用服务器版本] [保留我的输入并重新保存] [复制到备注]
```

# 11. 报告投影、既有对比矩阵共存与快照

## 11.1 报告侧原则

1. 报告页不允许编辑动态数据矩阵的结构、字段、值、公式、证据或问题。
2. 报告从 `MatrixReportProjection` 读取动态数据矩阵。
3. 当前既有“对比矩阵”继续按现有逻辑展示，不被本模块替代。
4. 同一报告可以同时出现：功能效果、五感体验、既有对比矩阵、动态数据矩阵。
5. 动态数据矩阵区块必须展示矩阵名称，避免与既有对比矩阵混淆。
6. 已发布报告只读取快照，不读取任务实时矩阵。

## 11.2 报告动态结果区的区块顺序

建议默认顺序：

```text
问题点列表
  -> 功能/食谱效果（既有）
  -> 五感/操作（既有）
  -> 对比矩阵（既有，如适用）
  -> 数据矩阵（新增，如适用）
  -> 指标明细与来源追溯
```

系统可根据有无数据隐藏不存在的区块，但不得把不同模块的数据混成同一个无标题表格。

## 11.3 动态数据矩阵报告区

```text
数据矩阵：原汁效果对比矩阵
可比性：部分可比
限制：不同食材批次和环境温度存在差异。

筛选：
[全部] [仅异常] [仅未完成] [仅有关联问题] [仅关键字段]

分组 / 行 / 用户定义字段 / 证据 / 问题
```

# 12. API 契约与后端实现要求

## 12.1 通用接口约束

- API 前缀：`/api/v1`。
- 所有写接口必须支持 `Idempotency-Key`。
- 所有更新接口必须传 `If-Match` 或显式 `version`。
- 所有接口返回 `trace_id`、`request_id`、`data`、`error`。
- 所有接口在服务端执行任务资源范围权限校验。
- 所有归档为软归档，不允许破坏快照引用。
- JSONB 仅用于可扩展配置和快照，不得将可筛选、可审计、可计算的核心字段塞入大 JSON。

## 12.4 公式引擎安全要求

1. 使用受控 AST 解析器；禁止字符串 `eval`。
2. 字段引用必须转换为内部字段 ID。
3. 公式函数白名单由平台管理员配置。
4. 单次计算最大执行时长不超过 200ms；超时标记运行失败。
5. 单次重算最多影响当前行的 15 个计算字段。
6. 公式依赖图必须无循环；服务端为最终判定方。
7. 每次计算写入 `MatrixCalculationRun`。

| 矩阵投影重建 | 结构/事实变更后 | 指数退避；失败不丢事实，报告显示最近成功投影与更新时间。 |
| 报告快照捕获 | 报告发布 | 阻断发布完成，直到快照捕获成功。 |
| 搜索索引 | 设计或内容变更 | 失败可重试，不影响事实保存。 |

# 15. 非功能需求

## 15.1 性能指标

| 指标 | P0 目标 |
|---|---|
| 单矩阵最大活跃行数 | 500 行 |
| 单矩阵最大字段数 | 40 个 |
| 单矩阵最大计算字段数 | 15 个 |
| 单任务最大活跃矩阵数 | 10 个 |
| 单槽位最大媒体数 | 10 个 |
| 首次加载 100 行 × 30 字段 | P95 ≤ 2 秒 |
| 单字段保存 | P95 ≤ 1.5 秒 |
| 单行公式重算 | P95 ≤ 1 秒 |
| 提交前矩阵校验 | P95 ≤ 5 秒 |
| 报告投影重建 | P95 ≤ 10 秒 |

超出阈值时，系统必须提示用户拆分矩阵、缩小范围或按分组录入；不得无提示卡死。

## 15.2 安全要求

- 字段名、分区名、说明、备注必须做 XSS 转义。
- 公式使用受控 AST，不执行用户输入字符串。
- 公式只能引用同一行且已确认版本字段。
- 批量粘贴内容不得作为 HTML、脚本或公式执行。
- 媒体沿用短期签名 URL、扫描、转码、权限校验和访问审计。
- 所有接口必须执行 Task Resource Scope 权限校验。
- 已发布快照引用的数据和媒体不得硬删除。

## 15.3 可访问性

- 所有字段均有明确标签。
- 不以颜色作为唯一错误提示。
- 计算失败必须同时显示失败原因文本。
- 手机端核心录入无需横向滚动。
- 桌面端支持键盘 Tab/Shift+Tab 切换字段。

# 附录 A：Excel 示例向动态数据矩阵的映射方式

以下示例只用于说明映射思路，不构成系统默认模板。

```text
矩阵名称：口径 × 食材效果对比

一级分组名称：食材
行名称：口径

分区：测量记录
- 测试时长（时长）
- 原料重量（数值，g）
- 成品重量（数值，g）
- 果渣重量（数值，g）

分区：计算结果
- 出品率（计算百分比）
  {成品重量} / {原料重量}

分区：体验观察
- 体验结果（单选）
  符合预期 / 待观察 / 未符合预期 / 不适用
- 过程说明（多行文本）

分区：证据与问题
- 效果图（图片槽位）
- 操作视频（视频槽位）
- 关联问题（问题槽位）

分组级：分组小结（多行文本）
矩阵级：总体小结、测试备注（多行文本）
```

关键解释：

- Excel 中的“食材”“口径”“重量”“效果图”“小结”不是平台默认字段，只是这一份具体矩阵的用户设计结果。
- Excel 中 `=G4/G9` 等坐标公式不迁移；改为稳定字段引用，例如 `{成品重量}/{原料重量}`。
- Excel 中的图片不再贴在无语义单元格附近，而是绑定当前 MatrixRow、证据槽位、RecordItem，必要时再绑定 IssueOccurrence。
