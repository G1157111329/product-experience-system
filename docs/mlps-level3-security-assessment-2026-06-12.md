# 网络安全等级保护三级代码侧安全评估报告（最新版）

评估日期：2026-06-12  
评估对象：产品体验管理平台当前本地工作区最新代码  
评估方式：静态代码审查、关键安全模块抽查、API 鉴权覆盖扫描、数据库安全脚本核验、构建验证、依赖安全审计、Docker 本地模拟环境验证  
评估边界：本报告为代码侧安全差距识别与整改建议，不等同于正式等保测评结论；不覆盖机房、网络设备、主机基线、云控制台、堡垒机、备份演练、制度流程、人员管理等现场测评内容。

## 一、总体结论

当前版本已围绕网络安全等级保护三级关注的身份鉴别、访问控制、安全审计、恶意文件防范、错误信息保护、数据库安全策略、共享限速、部署配置和外部接口调用进行了系统性加固。

与上一轮代码状态相比，本次新增完成三项关键收口：

1. 移除开发环境硬编码默认管理员和数据库不可达时的本地管理员回退。
2. 上传接口增加扩展名白名单、MIME 白名单和文件魔数一致性校验。
3. 生产环境 API 顶层异常统一返回通用错误，不再向客户端回显内部异常信息。

代码侧未发现明显 P0 级上线阻断项。当前版本可进入目标环境上线前核验或内网试运行阶段。若面向公网或进入正式等保三级测评，仍需补充现场部署核验、日志集中告警、上传内容安全扫描、账号高级策略、备份恢复演练和安全运营制度。

综合判断：代码侧安全成熟度为中高；正式等保三级测评准备度为“可进入现场核验与试运行整改阶段”。本报告不能作为“已通过等保三级”的证明材料。

## 三、等保三级关注点评估

### 1. 身份鉴别

现状：

- 使用 `xp_session` 服务端签名会话 Cookie，具备 `httpOnly`、`sameSite=lax`，生产环境默认启用 `secure`。
- 生产环境强制要求 `AUTH_SESSION_SECRET`，缺失时启动失败。
- 密码使用 `scrypt` 加盐哈希，旧 SHA-256 哈希登录后可自动升级。
- 新密码策略要求至少 10 位，并同时包含字母和数字，拦截 `bear2026` 等弱口令。
- 已移除开发环境硬编码默认管理员凭证；本地和生产首次管理员均需显式配置 `INITIAL_ADMIN_ACCOUNT` 和 `INITIAL_ADMIN_PASSWORD`。
- 已移除数据库不可达时 `local-dev-admin` 管理员回退，并清理服务端对 `local-dev-admin` 的特殊放行。
- `INITIAL_ADMIN_ACCOUNT` 和 `INITIAL_ADMIN_PASSWORD` 必须成对配置，且启动时校验密码强度。
- 登录、注册、找回密码等入口接入共享限速和安全审计。

差距：

- 尚未实现 MFA、多因素认证。
- 尚未实现密码历史、定期更换、会话集中吊销列表。
- 账号锁定主要依赖限速策略，尚未形成完整的连续失败锁定、解锁审批和告警流程。

整改建议：

- 正式测评前补充账号锁定、会话吊销和密码历史策略。
- 如系统面向公网或跨组织访问，建议增加 MFA 或接入企业统一身份源。

### 2. 访问控制

现状：

- 业务 API 已统一使用 `requireUser`、`requireAdmin` 和 `canAccessTask`、`canAccessReport`、`canAccessMaterial`、`canAccessIssue` 等资源级判断。
- API 扫描显示，除登录、注册、找回密码、登出等认证入口外，业务接口均接入服务端认证或授权检查。
- 体验计划、素材、检查记录、食谱、问题点等写操作按任务归属进行服务端校验。
- 管理员接口使用 `requireAdmin` 限制。
- 报告中心保留“全部报告/个人报告”：普通登录用户可读取内部报告，编辑、分享、删除仍按归属或管理员权限控制。
- 前端 `useAuth()` 仅作为显示状态，不作为安全边界。

差距：

- “全部报告”属于业务协同需要，但扩大了内部可读范围，需要在权限制度中明确为内部共享资料，并配套账号实名、审计和离职清理。
- 当前报告可见范围尚未细化到项目组、产品线或品类级授权。

整改建议：

- 保留报告内部共享的同时，在制度和用户授权说明中明确“报告中心为登录用户内部共享区”。
- 后续可按产品线、项目组、品类等维度进一步细化报告可见范围。

### 3. 安全审计

现状：

- 已建立 `security_audit_logs` 表，记录动作、操作者、目标对象、结果、IP、User-Agent、路径、方法和元数据。
- 审计写入会过滤密码、Token、API Key、Cookie 等敏感字段。
- 重要操作已接入审计：未授权访问、权限拒绝、登录、账号管理、报告分享、报告删除、素材上传、AI 调用、数据导出、设置变更等。
- 数据库脚本为审计表增加只追加保护，阻断 UPDATE 和 DELETE。
- 已提供管理员审计日志查询接口 `/api/security/audit-logs`。

差距：

- 审计日志归档、保留周期、告警规则和异常行为分析仍属于现场/运维能力，当前代码只提供基础数据能力。
- 尚未接入集中日志平台或 SIEM。

整改建议：

- 上线前明确审计日志保留周期、备份周期和访问审批人。
- 正式测评前对连续登录失败、越权访问、批量上传、批量导出、分享链接大量访问等事件建立告警。

### 4. 文件上传与入侵防范

现状：

- 素材上传接口要求登录，并校验任务、记录、食谱、问题复评估等归属关系。
- 上传大小限制为 100MB，适配图片和视频证据的业务需求。
- 已增加扩展名白名单，允许 `jpg/jpeg/png/gif/webp/heic/heif/mp4/m4v/mov/webm`。
- 已增加 MIME 白名单，要求扩展名和 `Content-Type` 匹配。
- 已增加文件魔数校验，要求文件内容与声明类型一致，避免仅修改请求头绕过校验。
- 文件路径通过规范化和目录边界检查降低路径穿越风险。
- 上传成功写入安全审计。

差距：

- 当前为文件类型真实性校验，不等同于病毒扫描、木马查杀或内容安全识别。
- 对超大批量上传、单用户存储配额、隔离区扫描后入库等能力仍需增强。

整改建议：

- 正式测评前接入杀毒/恶意内容扫描，或建立上传隔离区和异步扫描流程。
- 为用户、任务或项目设置存储配额和异常上传告警。

### 5. 文件存储与素材访问

现状：

- 默认文件存储仍为 local 模式，写入 `public/uploads`，可切换 S3 兼容对象存储。
- local 模式默认保留 `/uploads/<key>` 稳定静态 URL，以保证内网部署、历史报告、分享页和 PDF 导出长期可视，避免素材过期裂图。
- 如部署环境需要更高访问控制，可显式设置 `LOCAL_UPLOAD_PUBLIC_ACCESS=protected`，通过 `/api/materials/file` 短期签名 URL 或登录态鉴权访问。
- 删除业务对象时以解除关联为主，减少误删素材导致历史报告裂图的风险。

差距：

- 默认静态直连可保证业务持久性，但素材 URL 泄露后可能被直接访问。
- local 存储的备份、归档、磁盘容量监控和防误删策略需要运维侧落实。

整改建议：

- 内网部署可维持 `LOCAL_UPLOAD_PUBLIC_ACCESS=public`，并通过网络边界、账号审计和备份保障安全。
- 公网部署建议评估 `protected` 模式或对象存储私有桶加签名 URL。
- 上线前明确素材目录持久化挂载、备份策略和恢复演练流程。

### 6. 数据库与 RLS

现状：

- `database-schema.sql` 会启用 RLS 并删除 `allow_all` 策略。
- 生产环境强制要求 `SECURITY_SCHEMA_VERIFIED=true`，用于确认目标库已执行安全 schema 和验证脚本。
- `scripts/verify-security-schema.sql` 会检查 `security_audit_logs`、`security_rate_limits` 是否存在，并阻断 `allow_all` 残留。
- 生产启动要求明确 `DATABASE_ACCESS_MODE`，区分自建 PostgreSQL 与 Supabase service role 模式。
- 本地 Docker PostgreSQL 已执行验证脚本，返回 `DO`。

差距：

- 本次仅验证本地 Docker 数据库；目标生产库仍需现场执行并保存结果。
- 如果使用 Supabase，需要现场确认 anon key 不承担业务写权限，service role 仅保存在服务端。

整改建议：

- 上线前在目标库执行 `database-schema.sql` 和 `scripts/verify-security-schema.sql`，保存命令、时间、执行人和结果。
- 固化数据库访问模式：自建 PostgreSQL 使用受控服务账号；Supabase 使用 service role 仅在服务端保存，前端不暴露。

### 7. 多实例限速与抗滥用

现状：

- 已建立 `security_rate_limits` 表，用数据库实现共享限速状态，适用于多实例部署。
- 登录、注册、找回密码、上传、标准导入等高风险入口接入限速。
- 生产环境下共享限速失败时返回 503，不静默降级为单实例内存限速。
- 开发环境保留内存限速兜底，方便本地调试。

差距：

- 尚未形成统一的限速监控看板和阈值调优记录。
- 对报告分享公开访问、AI 调用、批量导出等高成本路径仍可继续细化策略。

整改建议：

- 试运行期间记录限速命中情况，按真实使用量调整阈值。
- 对公开分享访问和 AI 调用增加独立限速指标。

### 8. AI 外联与密钥保护

现状：

- AI API Key 使用 `AI_CONFIG_ENCRYPTION_KEY` 加密保存，生产环境缺失该密钥时启动失败。
- AI 配置接口仅管理员可管理，返回时隐藏密钥明文。
- AI 调用会记录成功/失败审计，不记录完整密钥。
- 支持 `AI_ALLOWED_HOSTS` 白名单；当前未默认拦截内网、本机或 HTTP AI 地址，以兼容内网优先部署和本地模型服务。

差距：

- 未默认执行内网地址 SSRF 拦截，这是内网部署友好策略，但公网部署时需要额外治理。
- 尚未实现请求内容脱敏、敏感字段识别和 AI 调用成本/频率告警。

整改建议：

- 内网部署可保持当前策略；公网部署建议启用 `AI_ALLOWED_HOSTS`，仅允许明确的 AI 服务域名或网关。
- 对发送给 AI 的素材和文本建立脱敏规则，避免上传不必要的敏感信息。
- 建立 AI 调用审计复查和异常成本告警。

### 9. Web 安全、CSRF 与错误信息保护

现状：

- `proxy.ts` 对所有状态变更 API 的 `Origin` 和 `Referer` 做同源校验。
- 会话 Cookie 使用 `sameSite=lax`，降低常见 CSRF 风险。
- 生产环境 API 顶层异常统一返回 `Internal server error`，详细错误只记录在服务端日志，降低内部路径、数据库信息和堆栈信息泄露风险。
- 生产环境可对 `/uploads/*` 启用直连拦截，但当前默认不拦截，符合内网部署和素材持久展示要求。

差距：

- 当前 CSRF 防护是同源校验方案，不是显式 CSRF Token 方案。
- CSP 仍可继续收紧，尤其是脚本、样式和图片域名策略。

整改建议：

- 当前同源校验可作为基础防护；若面向公网或高等级审计，建议增加显式 CSRF Token。
- 上线前根据实际域名、对象存储域名、AI 网关域名收紧 CSP 和连接白名单。

### 10. 供应链与构建发布

现状：

- TypeScript 检查通过。
- 生产构建通过。
- 官方 npm registry 审计显示当前无已知漏洞。
- Docker 本地模拟环境健康，可用于部署前回归。
- 生产启动安全校验集中在 `startup-security.ts`，缺少关键环境变量会失败。
- README 和 AGENTS 已更新为最新部署口径：服务器上线仍按 Node.js + PostgreSQL + 反向代理，Docker 仅作为本地模拟环境；默认 local 存储不改变。

差距：

- CI 安全门禁需要持续执行，不能只依赖人工本地命令。
- 需要在部署流水线中固定执行 `pnpm ts-check`、`pnpm build`、`pnpm audit`、数据库验证记录检查。

整改建议：

- 保留并持续完善 GitHub Actions 或内部 CI 安全门禁。
- 锁定 pnpm 版本和 Node.js 版本，避免构建环境漂移。

## 六、上线前核验清单

1. 在目标生产数据库执行 `database-schema.sql`。
2. 在目标生产数据库执行 `scripts/verify-security-schema.sql`，确认无 `allow_all`，且 `security_audit_logs`、`security_rate_limits` 存在。
3. 生产环境设置并核验 `SECURITY_SCHEMA_VERIFIED=true`。
4. 明确 `DATABASE_ACCESS_MODE`，并确认前端不暴露 service role 或高权限数据库凭据。
5. 设置强随机 `AUTH_SESSION_SECRET`、`AI_CONFIG_ENCRYPTION_KEY`。
6. 如需首次管理员，临时设置 `INITIAL_ADMIN_ACCOUNT` 和强密码，初始化后移除。
7. 确认 `LOCAL_UPLOAD_PUBLIC_ACCESS` 与部署边界一致：内网可为 `public`，公网建议评估 `protected` 或私有对象存储。
8. 确认 `public/uploads` 已挂载持久化磁盘或切换到 S3 兼容对象存储。
9. 如使用 AI，配置 `AI_ALLOWED_HOSTS` 或内网 AI 网关，并保存外联审批记录。
10. 执行 `pnpm ts-check`、`pnpm build`、`pnpm audit --audit-level moderate --registry https://registry.npmjs.org`。
11. 执行登录、上传素材、生成报告、分享报告、删除/撤销、审计查询的回归验证。
