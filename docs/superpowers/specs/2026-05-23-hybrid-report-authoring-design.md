# Hybrid Report Authoring Design

## Goal

重构报告录入和编辑链路，让体验工程师可以更顺畅地完成“整理素材证据 -> 结构化录入事实 -> 预览报告草稿 -> 生成报告 -> 轻量调整文字 -> 分享/导出”的完整流程。

核心原则是：**事实层回源编辑，表达层报告内编辑**。

## Current Problem

当前产品链路更像：

`任务详情分散录入 -> 点击生成报告 -> 报告中心只读查看`

主要问题：

- 工程师在任务详情页录入五感记录、功能步骤、效果评价、素材时，不清楚这些内容最终进入报告的哪个部分。
- 报告生成前缺少草稿预览和输入质量检查，容易生成后才发现缺素材、缺问题描述、AI 总结不完整。
- 报告中心只能查看和分享，轻量文字调整能力不足，但第一阶段不把它改成独立评审流。
- 报告生成后发现事实错误时，用户需要自己回到任务详情页寻找对应字段，回源链路不明确。
- 如果以后允许直接编辑整份报告，会出现报告内容与原始任务数据不一致的风险。

## Editing Boundary

### Source Data: Edit In Task Detail

这些内容属于事实层，必须回到任务详情页编辑：

- 任务基础信息：品类、产品、型号、项目类型、阶段、测试目标。
- 五感体验记录：检查项、检查结果、问题描述、问题等级、标准字段。
- 图片/视频素材及证据绑定。
- 食谱/功能：名称、参数、步骤、步骤问题点、步骤素材。
- 效果/出品评价：效果描述、效果素材、AI 评分、效果问题点。
- 自动创建问题的来源数据。

原因：这些内容是报告、问题管理、PDF、分享页的共同事实来源，不能在报告页形成第二套数据。

### Report Data: Edit In Report Detail

这些内容属于表达层，后续可以在报告详情页做轻量编辑；第一阶段先以最终输出预览、分享、打印和回源编辑为主：

- 报告标题。
- AI 总评/人工总评。
- 主要优势。
- 主要风险。
- 历史表现判断。
- 后续建议。
- 内部备注。

原因：这些内容是报告表达，不应该为了改一句话回到任务详情页。但该能力不应把报告中心变成重型评审工作流。

## New User Flow

### 1. Task Detail Becomes Material-First Input Workspace

任务详情页从普通四 Tab 页面升级为“素材优先录入工作台”。

这里的核心不是先做报告评审，而是承接体验工程师的真实工作方式：

`手机拍摄图片/视频 -> 回到电脑整理素材 -> 绑定到五感记录/功能步骤/效果评价 -> 写问题描述和报告文字 -> 生成报告`

因此素材证据不是报告附件，而是事实录入的起点。

桌面端默认布局：

- 左侧：录入目录与工具入口。
- 右侧：源数据录入区。

录入目录建议：

- 素材证据。
- 五感体验。
- 功能效果。
- AI 总结/报告。

右侧录入区结构：

- 顶部固定展示“素材证据栏”，跨五感体验和功能效果共享。
- 下方展示当前录入模块，例如五感体验记录区或功能效果工作区。
- 当前记录/步骤内部只展示“已绑定证据”，不重复渲染完整素材仓库。

素材证据栏职责：

- 展示任务下所有图片/视频素材，图片和视频都要有足够大的缩略图。
- 支持上传、拍照/录像入口、批量选择、预览。
- 支持筛选：未关联、已关联、图片、视频、五感、功能、效果。
- 支持将素材绑定到当前五感记录、功能步骤或效果评价。
- 后续可支持拖拽素材到记录/步骤，第一阶段可以先用选中后绑定。

Agent 辅助不再作为常驻“报告就绪度”侧栏。默认界面不显示右侧 Agent 面板，避免压缩素材和录入空间。

Agent 唤醒规则：

- 左侧目录顶部放置 AI 图标按钮。
- 未唤醒时是两栏：左侧目录、右侧录入区。
- 唤醒后变为三栏：左侧目录、中间录入区、右侧 Agent 辅助栏。
- Agent 辅助栏应保持窄宽度，建议约 `260px-300px`。
- Agent 只负责聊天式建议、缺口提醒、未关联素材定位、报告草稿辅助，不自动替代工程师录入事实。

移动端布局：

- 不使用三栏。
- 顶部展示模块切换或目录抽屉。
- 素材证据栏优先展示，可横向滑动或进入全屏素材池。
- Agent 作为底部抽屉唤醒，默认关闭。

### 2. Source Input Modules

#### 五感体验

五感体验从“大弹窗新增问题点”改为更接近工作台的录入方式：

- 左侧/上方：记录列表，按标准类型、感官维度、检查结果、问题等级筛选。
- 右侧/下方：当前记录编辑区。
- 编辑区展示标准字段、检查结果、问题描述、问题等级和已绑定证据。
- 新增记录可以从快捷入口开始：标准引用、非标准快速记录、感官评分记录。
- 复杂标准字段可渐进展开，避免一开始暴露过多表单。
- 保存后记录立即回到列表，工程师可以连续录入下一条。

#### 功能效果

功能效果从“展开食谱卡片后编辑所有内容”改为“功能工作区”：

- 左侧/上方：食谱/功能列表。
- 中间：当前功能的步骤时间线。
- 右侧/下方：效果/出品评价、效果问题点和已绑定证据。
- 步骤支持内联查看和快速编辑，复杂编辑可保留弹窗作为第二层入口。
- 每个功能显示轻量完成状态：步骤数、已绑定素材数、效果描述是否填写、效果问题点数量、AI 评分状态。
- 素材证据仍然从顶部素材栏选择或绑定，步骤内部只展示已绑定证据。

### 3. Add Draft Preview Before Generation

点击“报告生成”不应直接生成最终报告，而是进入生成前确认流程：

1. 展示报告草稿预览。
2. 展示输入质量检查结果。
3. 如果有关键缺口，允许用户回源修复。
4. 用户确认后生成报告。

不做硬阻断，除非任务基础信息缺失到无法生成报告。

### 4. Report Detail As Final Output Preview

报告详情页第一阶段不再承担重型评审编辑器职责，而是作为在线工作流里的最终输出预览、分享和导出入口。

桌面端布局：

- 中间：报告正文。
- 顶部/右上：分享、打印/PDF、重新生成、回源编辑等操作。

报告正文分为两类区域：

- 表达区：标题、总评、优势、风险、历史表现、建议。
- 只读事实区：检查记录、食谱步骤、效果评价、素材证据、自动问题。

只读事实区提供“回源编辑”入口：

- 检查记录 -> 跳转任务详情五感体验，并定位记录。
- 食谱步骤 -> 跳转任务详情功能效果，并展开对应食谱。
- 效果评价 -> 跳转任务详情功能效果，并定位效果评价。

第一阶段可以先跳到对应 Tab，不要求精确滚动到字段；第二阶段再做锚点定位。

报告中心不放置常驻“报告评审编辑栏”。后续如需要人工润色报告表达，应作为轻量编辑能力出现，而不是把报告中心改成独立评审流。

### 5. Regeneration Keeps Manual Edits

重新生成报告时，系统应刷新事实快照，但保留人工润色字段。

保留字段建议存放在 `report.content.review_overrides`：

```json
{
  "title": "人工修改后的标题",
  "ai_summary": {
    "tag": "人工修改后的标签",
    "satisfaction_score": 8,
    "summary": "人工润色后的总评",
    "strengths": ["优势1"],
    "risks": ["风险1"],
    "historical_position": "历史表现判断",
    "suggestions": ["建议1"]
  },
  "review_note": "评审备注",
  "review_status": "reviewed",
  "updated_at": "2026-05-23T00:00:00.000Z"
}
```

显示报告时：

- 如果存在 `review_overrides.ai_summary`，优先显示人工润色版本。
- 否则显示生成时写入的 `content.ai_summary`。

重新生成时：

- 读取旧报告的 `review_overrides`。
- 重新生成事实内容。
- 将旧 `review_overrides` 写回新报告。
- 默认不覆盖人工润色。
- 如果用户选择“重新生成并覆盖人工润色”，才清空 `review_overrides`。

## AI Agent Assistance Layer

### Goal

在报告录入工作区之上增加“产品体验 Agent 辅助层”，让 AI 不只是生成评价文字，而是参与体验走查前的任务理解、重点检查预设、食谱/功能场景预设、效果评价和报告总结。

核心原则：

- Agent 产出是“建议态预设”，不是事实结论。
- 工程师必须确认后才写入五感体验记录、食谱/功能或报告表达字段。
- 检查结果、问题描述、素材证据仍由工程师现场录入，Agent 不自动填充。
- 管理员可以配置模型、维护 skills 模板、启停模板、查看版本和审计记录。

### Admin AI Settings Center

管理员账号设置中新增“AI Agent 设置”入口，包含两个一级区域：

1. 模型接入。
2. Skills 模板管理。

模型接入支持：

- 内置模型。
- 自定义 OpenAI Chat Completions 兼容 API。
- API 地址、API Key、模型名、温度、最大 token、视觉能力开关。
- 测试连接按钮，返回一次最小化模型响应。

Skills 模板管理包含 4 个业务入口：

1. 五感体验标准预设 Skill。
   - 输入：体验目的、品类、产品、项目类型、项目阶段、目标用户、测试方法。
   - 输出：推荐标准类型、标准检查项 ID、推荐理由、重点检查说明。
   - 写入方式：用户确认后批量创建检查记录草稿，检查结果、问题描述、素材为空。

2. 食谱/功能/场景筛选 Skill。
   - 输入：体验目的、品类、产品、项目类型、项目阶段、已有食谱库、可选热点摘要。
   - 输出：推荐食谱/功能、食材/参数、步骤草稿、引用来源、推荐理由。
   - 写入方式：用户确认后创建或引用食谱/功能，步骤和食材/参数可预填，效果评价、问题点、素材为空。

3. 效果评价 Skill。
   - 输入：食谱/功能名称、食材/参数、步骤、效果描述、效果素材。
   - 输出：综合评分、总结评语。
   - 约束：四维评价框架可以作为内部方法论，但对外仍只展示综合评分和总结。

4. 报告总体总结 Skill。
   - 输入：任务信息、五感记录、食谱/功能、效果评价、素材摘要、历史同品类同产品报告。
   - 输出：满意度分数、体验标签、总评、优势、风险、历史表现判断、后续建议。
   - 写入方式：生成 AI 总结草稿，用户可在任务详情或报告详情中做轻量调整。

“新建体验任务后的体验目的理解”作为 Agent 编排步骤，不单独暴露为第 5 个入口。它在调用五感体验标准预设 Skill 和食谱/功能/场景筛选 Skill 前执行，负责把用户输入的体验目的转换为结构化意图：

```json
{
  "intent_tags": ["新品首测", "出品稳定性"],
  "risk_focus": ["口感一致性", "操作易错点"],
  "scenario_keywords": ["早餐", "多人份", "快速出品"],
  "standard_search_keywords": ["稳定性", "清洁", "噪音"],
  "recipe_search_keywords": ["豆浆", "米糊", "果蔬汁"]
}
```

### Independent Data Model

由于 skills 需要版本管理、启停和审计，不再只存入 `platform_settings`。新增独立表承载 Agent 配置。

#### `ai_model_configs`

保存模型接入配置。

| 字段 | 说明 |
|------|------|
| `id` | 配置 ID |
| `name` | 配置名称，如“默认内置模型”“OpenAI兼容API” |
| `provider` | `builtin` / `custom` |
| `model` | 模型名 |
| `temperature` | 温度 |
| `max_tokens` | 最大 token |
| `supports_vision` | 是否支持图片输入 |
| `custom_api_url` | 自定义 API 地址 |
| `custom_api_key_encrypted` | 加密后的 API Key |
| `is_active` | 是否为当前启用配置 |
| `created_by` | 创建管理员 |
| `created_at` / `updated_at` | 时间戳 |

第一阶段同一时间只允许一个 active 模型配置。后续如需按 skill 指定模型，可在 `agent_skill_templates.model_config_id` 上扩展。

#### `agent_skill_templates`

保存 skill 的当前主记录和启停状态。

| 字段 | 说明 |
|------|------|
| `id` | Skill ID |
| `skill_key` | 固定枚举：`senses_standard_preset` / `recipe_scene_preset` / `effect_evaluation` / `report_summary` |
| `name` | 展示名称 |
| `description` | 管理员维护说明 |
| `is_enabled` | 是否启用 |
| `active_version_id` | 当前启用版本 |
| `model_config_id` | 可选，指定模型配置；为空则使用默认 active 模型 |
| `created_by` | 创建管理员 |
| `created_at` / `updated_at` | 时间戳 |

禁用某个 skill 后：

- 普通用户不显示该 Agent 操作按钮。
- 已有由该 skill 生成的草稿数据不删除。
- 审计记录保留。

#### `agent_skill_versions`

保存每次模板变更的不可变版本。

| 字段 | 说明 |
|------|------|
| `id` | 版本 ID |
| `template_id` | 对应 `agent_skill_templates.id` |
| `version` | 递增版本号，如 `1`、`2` |
| `system_prompt` | 系统提示词 |
| `user_prompt_template` | 用户提示词模板，支持变量占位 |
| `output_schema` | 期望 JSON 输出结构 |
| `notes` | 版本说明 |
| `created_by` | 创建管理员 |
| `created_at` | 创建时间 |

版本创建后不允许原地修改。管理员编辑 skill 时实际创建新版本，再选择是否设为 active。

#### `agent_skill_audit_logs`

保存配置变更和运行审计。

| 字段 | 说明 |
|------|------|
| `id` | 审计 ID |
| `skill_key` | Skill 类型 |
| `template_id` | Skill ID |
| `version_id` | 调用或变更时使用的版本 |
| `action` | `create_version` / `activate_version` / `enable` / `disable` / `run` / `accept_suggestion` / `reject_suggestion` |
| `actor_user_id` | 操作人 |
| `task_id` | 相关任务，可为空 |
| `request_snapshot` | 调用输入摘要，避免保存完整敏感素材 |
| `response_snapshot` | 模型输出摘要 |
| `status` | `success` / `failed` |
| `error_message` | 失败信息 |
| `created_at` | 时间戳 |

审计目标不是追踪所有 token 细节，而是回答三个产品问题：

- 当前任务的预设建议由哪个 skill 版本生成？
- 工程师采纳或拒绝了哪些建议？
- 管理员何时启停或切换了模板版本？

### Suggested Preset Skill Packs

系统可内置以下预设包作为初始版本，管理员可复制后调整：

- 新品首测：强调基础体验路径覆盖、风险发现和证据完整。
- 竞品研究：强调差异点、同价位体验预期和竞品对比。
- 改型降本：强调历史问题复测、材料/结构变化带来的体验退化。
- 海外产品：强调语言标识、当地使用习惯、电压/场景适配。
- 食谱功能验证：强调食材参数、步骤可复现、出品稳定性。
- 问题复测：强调旧问题闭环、验证证据和整改有效性。

### User Flow: Agent Preset After Task Creation

新建体验任务成功后，任务详情页顶部显示“Agent 预设建议”入口。

流程：

1. Agent 读取任务基础信息和体验目的。
2. Agent 生成结构化体验意图。
3. 用户选择运行“五感体验标准预设”“食谱/功能/场景筛选”或一键运行两者。
4. 系统展示建议清单，不直接写入事实数据。
5. 工程师勾选要采纳的检查项、食谱或步骤。
6. 用户确认后写入：
   - 五感体验检查记录草稿。
   - 食谱/功能和步骤草稿。
7. 审计日志记录 skill 版本、输入摘要、输出摘要和采纳结果。

预设五感体验记录的默认值：

- `evaluation_result`: `待定`
- `problem_description`: 空
- 素材关联：空
- 标准字段：由选中的标准检查项带入

预设食谱/功能的默认值：

- 名称、食材/参数、步骤：由 Agent 或食谱库引用预填。
- 效果描述：空。
- 效果问题点：空。
- 素材关联：空。

### Hotspot Data Boundary

“搜索进度热点”第一阶段不直接做开放互联网搜索，避免不稳定、不可审计和数据权限问题。建议采用可审计的热点输入源：

- 管理员在 skill 设置中维护“热点摘要”文本。
- 或从内部历史报告、食谱库、问题管理中提取高频问题与高频场景。
- 后续如接入外部搜索服务，需要把搜索 query、搜索时间、摘要结果写入审计日志。

## PDF Export Performance Layer

### Current Problem

报告中心导出 PDF 当前借用浏览器打印能力。打印页会等待报告中所有图片加载并转换为 base64 后再调用 `window.print()`。当附录图片很多时，导出会出现以下问题：

- 等待时间长，用户误以为页面卡住。
- 同一素材在记录、步骤、效果评价、附录中重复出现时会重复转换。
- 原图体积过大，浏览器内存压力和 PDF 体积都会显著上升。
- 用户无法区分日常评审需要的快速 PDF 和归档需要的高清 PDF。

### Export Modes

第一阶段保留浏览器打印链路，但增加导出模式：

- `fast`：默认模式。图片去重、限并发、压缩到适合打印预览的尺寸后再打印。适合日常评审和分享。
- `high`：高清模式。保留原图 base64 转换逻辑，适合正式归档，但速度较慢。
- `text`：无图模式。跳过图片转换，正文、问题清单、评分和结论优先，适合快速看文字结论。

报告中心、报告详情页、分享页默认打开 `fast` 模式：

```text
/reports/print?id=<report_id>&mode=fast
```

如果用户选择高清导出，则打开：

```text
/reports/print?id=<report_id>&mode=high
```

### First Phase Optimization

打印页优化规则：

- 收集图片 URL 时先去重。
- 图片转换限制并发，避免一次性拉取所有大图。
- `fast` 模式将图片压缩为 JPEG，最长边不超过 1200px，质量约 0.72。
- `high` 模式保持原图 data URL。
- `text` 模式不等待图片转换，图片可隐藏或保留远程 URL，但不阻塞打印。
- 打印页展示当前模式和图片处理状态，避免用户误以为卡死。

### Later Server-Side Option

如果后续仍然慢，再做服务端 PDF 生成与缓存：

- 后端读取报告内容和素材缩略图。
- 服务端生成 PDF 文件并保存。
- 同一报告内容未变化时直接下载缓存。
- 用户电脑不再承担图片转换和排版压力。

## API Changes

### First Phase

第一阶段以任务详情页源数据录入重构为主，优先复用现有 API：

- 素材上传和关联继续复用 `/api/materials`。
- 五感记录继续复用 `/api/records`。
- 食谱/功能继续复用 `/api/recipes`、`/api/recipe-steps`。
- 报告生成继续复用 `/api/reports`。
- 不新增数据库字段。

如果素材关联现有接口不足，可以在现有 `/api/materials` 的更新能力上补充轻量参数，但不引入新的事实表。

### Optional Report Text Overrides

报告表达层轻量编辑仍可沿用 `report.content.review_overrides` 作为未来扩展，但它不是本阶段的主工作。

如果启用该能力：

- 复用现有 `PUT /api/reports/[id]`。
- 前端只提交局部合并后的 `content`，避免覆盖事实内容。
- 删除旧报告前，读取旧报告的 `content.review_overrides`。
- 生成新 `reportContent` 后，将旧 overrides 合并回去。
- 支持请求参数 `preserve_review_overrides`，默认 `true`。

## Print And Share Behavior

打印页和分享页也需要读取最终展示版本：

- 优先使用 `content.review_overrides.ai_summary`。
- 标题优先使用 `content.review_overrides.title`。
- 内部备注第一阶段只在详情页展示，不进入公开分享页。

## Implementation Phases

### Phase 1: Material-First Input Workspace

- 新增 `ReportAuthoringShell` 双态布局。
- 新增 `MaterialEvidenceRail`，将任务素材池放在源数据录入区顶部。
- 调整任务详情页桌面端布局：默认两栏，Agent 唤醒后三栏。
- 移动端保留单列结构，素材证据优先展示，Agent 用底部抽屉。

### Phase 2: Senses Input Redesign

- 将五感体验改为记录列表 + 当前记录编辑区。
- 保留复杂字段能力，但把高频录入路径前置。
- 支持从顶部素材证据栏绑定素材到当前记录。
- 保留原新增/编辑弹窗能力作为过渡兜底，确保功能不丢失。

### Phase 3: Functions Input Redesign

- 将功能效果改为食谱/功能列表 + 步骤时间线 + 效果评价区。
- 支持步骤快速编辑和效果问题点录入。
- 支持从顶部素材证据栏绑定素材到步骤、效果评价和效果问题点。
- 保留复杂编辑弹窗作为第二层入口。

### Phase 4: Agent Assistance And Report Generation

- 左侧目录增加 AI 图标唤醒入口。
- Agent 侧栏提供未关联素材定位、缺口提醒、总结草稿辅助。
- 报告生成前进入草稿预览和确认流程。
- 报告中心保持在线工作流入口，不增加常驻评审编辑栏。

## Success Criteria

- 工程师能先整理手机拍摄的图片/视频，再把素材绑定到五感记录、功能步骤和效果评价。
- 素材证据栏在桌面端足够靠前、足够大，工程师不需要频繁打开附件才能判断内容。
- 五感体验可以连续录入，不再主要依赖大弹窗完成高频操作。
- 功能效果可以围绕一个食谱/功能完成步骤、效果、问题点和素材绑定。
- Agent 默认不打扰录入，唤醒后能帮助定位缺口和未关联素材。
- 工程师生成报告前能预览草稿，而不是生成后再发现问题。
- 报告事实内容和任务源数据保持一致。
- 重新生成报告不会默认覆盖人工润色内容。
- 打印页和分享页展示与报告详情页一致的最终文本。

## Out Of Scope

- 不做完整富文本编辑器。
- 不允许在报告页直接修改检查记录、素材、食谱步骤等事实数据。
- 不把报告中心改造成独立评审流。
- 不重做数据库结构，第一阶段优先使用现有素材、记录和食谱数据结构。
- 不改变问题自动创建的事实来源。
