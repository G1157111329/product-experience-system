# 全平台 UI/UX 盘点与统一改造设计

## 1. 决策

不将体验计划孤立改版。先以产品体验工程师的完整工作链为主线，建立统一的页面外壳、信息层级和交互规则，再分批改造页面。

核心工作链：

```text
工作台主页 → 体验计划 → 五感/食谱功能/矩阵 → 问题管理 → 报告信息 → 冻结报告查看
```

已冻结报告详情、分享、打印和 PDF 下载属于保护区，不纳入本次视觉或交互改造。

## 2. 全局设计标准

平台定位为“证据密集型的专业工作台”，优先让体验工程师看清当前任务、上下文、待办、问题和素材，而不是使用营销式大卡片或重新制作第二套业务数据。

### 2.1 布局

- 复用现有平台全局左侧导航：工作台主页、标准管理、体验计划、问题管理、报告中心、数据分析、AI 助手。
- 桌面端使用可收起侧导航；移动端保留顶部导航/底部主导航，避免业务内容横向滚动。
- 统一页面结构：页面标题和主操作、状态/摘要、筛选或任务上下文、主要工作区、辅助信息或素材证据区。
- 任务内允许第二层“食谱/功能目录”或“记录目录”，但不得复制全局导航。
- 主工作区最多一个主操作；次级操作用 outline/ghost 样式。
- 编辑默认采用原位直接编辑：点击文本、数值、食材、步骤、问题结论即可编辑；失焦或 `Enter` 自动保存；`Esc` 放弃未保存改动；拖拽排序自动保存并显示保存状态。不得要求用户先点击“编辑”、进入编辑模式、再额外点击保存。
- 只有复杂媒体编辑、复杂矩阵配置、批量操作等才允许打开侧栏或弹窗；删除、覆盖、冻结/发布、权限和配置等高风险操作必须二次确认。

### 2.2 信息与交互

- 状态要使用文字、数字和语义色共同表达，不能只依赖颜色。
- 图标按钮必须有可访问名称和足够点击区域；正式实现使用现有 Lucide 图标体系，不使用 emoji。
- 图片/视频在业务结论中直接呈现缩略图，在任务级素材区集中筛选、预览和绑定；不把大量媒体塞进矩阵单元格。
- 列表数量大时采用筛选、窗口化读取、缩略图/封面惰性加载；移动端不产生主内容横向滚动。
- AI 只能给出草稿或变更提案；影响数据的操作必须经用户确认并可审计。

### 2.3 Hermes 全平台操作规则

网页内 Hermes、个人微信 ClawBot、后续企微渠道均是同一平台动作能力的不同入口。它们必须读取当前用户权限与任务/页面/选中对象上下文，并经统一动作契约调用平台原有业务 API；不得建立第二套事实数据。

- 非敏感操作：如文本、数值、食材、步骤、素材归属、问题描述、草稿生成等，在用户明确表达意图后可直接执行，并返回结果；可逆操作应提供短时撤销或回退入口。
- 敏感操作：删除、批量覆盖、权限、平台配置、冻结/发布、外发分享、不可逆导出等，必须展示影响范围并获得二次确认。
- 所有 Hermes 动作写入审计日志；失败时保留用户原输入并显示可理解的失败原因，不丢失编辑内容。

### 2.4 既有组件优先复用

优先统一和扩展现有 `PageShell`、`PageHeader`、`FilterBar`、`MetricCard`、`EntityListItem`、`StatusBadge`、`MediaGallery` 和全局 `navigation`，而不是每页重新写一套卡片、筛选和空状态。

## 3. 页面盘点与改造级别

| 页面/模块 | 级别 | 目标 | 业务逻辑改动 |
|---|---|---|---|
| 工作台主页 | P1 | 从统计首页变为“我的当前任务、待处理问题、待确认素材、待生成总结/报告”的行动工作台 | 否，优先复用现有统计和列表接口 |
| 标准管理 / 食谱库 | P1 | 建立清晰的库管理、检索、引用和版本入口；减少管理对话框的认知跳转 | 可能，需要结构化食材/步骤后同步展示 |
| 体验计划列表 | P1 | 强化任务状态、进行中入口、问题和报告进度；保留筛选与创建 | 否 |
| 体验计划详情 | P0 | 按已确认的食谱主线、功能效果评价、问题点输出、素材证据区和模块状态卡改造 | 是，见任务详情规格 |
| 五感体验 | P0 | 使用统一工作台外壳，独立编辑五感结论和问题点输出，并带入食谱/步骤上下文 | 是，需要记录上下文关联 |
| 单一食谱/功能 | P0 | 食材参数、动态步骤、功能效果评价、问题点输出和直接媒体呈现 | 是，需要结构化食材/步骤参数 |
| 对比矩阵 / 数据矩阵 | P1 | 保留现有专业编辑版式；数据矩阵首次进入自动创建空实例；支持清空、停用和对象删除；仅有实质内容时进入报告 | 需要统一有效内容判断与报告过滤 |
| 素材仓库 / 证据区 | P0 | 任务级常驻筛选、绑定、预览；兼顾海量素材性能 | 可能，需要分页/窗口化接口 |
| 问题管理 / 问题详情 | P0 | 承接各编辑页的正式问题点输出，显示来源任务、食谱/步骤、五感、证据和整改闭环 | 是，需要来源关联 |
| 报告中心列表 | P1 | 提升报告状态、生成时间、来源任务和入口的可读性 | 否或轻量聚合 |
| 冻结报告详情、分享、打印、PDF | 冻结 | 当前版式和输出保持不变 | 禁止改动 |
| 数据分析 | P2 | 统一筛选区、指标卡、图表层级和空/错误状态 | 否 |
| AI 助手 | P1 | 明确全局助手与任务内 Hermes 的职责；任务内入口优先使用当前上下文 | 可能，取决于 AI 提案契约 |
| 登录、个人设置、管理员设置 | P2 | 统一视觉、表单反馈和可访问性，不改变认证/权限逻辑 | 否 |

## 4. 核心业务页面的共同规则

### 4.1 工作台主页

主页不是展示全部统计的终点，而是当天/当前工作的起点。首屏按用户身份提供：继续进行的体验计划、待处理问题、待确认问题点输出、待归属素材、最近报告和快捷开始动作。管理员保留审核和全局指标，但不覆盖工程师的日常任务入口。

### 4.2 体验计划与五感/功能编辑

任务详情遵循已确认的任务详情规格：食谱/功能为主线；食材在新建时完整录入，常态以当前食谱标题下的紧凑标签显示并通过小浮层修改；功能效果评价中直接显示关联图片/视频；步骤多时局部滚动；任务级素材区在主工作区底部全宽常驻。

五感编辑页不复用功能效果评价或食材参数。五感和功能编辑都必须能输出结构化问题点；问题管理只负责整改、复评和关闭，不承担工程师第一次描述问题的职责。

### 4.3 问题管理

问题管理默认显示问题来源、当前状态、证据、责任人和复评信息。由任务页进入时，应自动带入任务、食谱/功能、步骤或五感记录筛选，避免工程师重新查找上下文。

### 4.4 报告边界

任务页的“报告信息”是原总结信息的状态与入口。`生成总结` 和 `生成报告` 继续走现有链路。冻结报告的详情、报告呈现、分享、打印、PDF 输出不得因共享组件、主题或路由重构而发生变化。

## 5. 数据/API 分层

### 5.1 仅前端改造

- 全局导航、页面标题、状态卡、筛选区、按钮层级、列表和空状态统一。
- 既有食谱/步骤/素材/报告接口的内容重排。
- 现有媒体文件预览和绑定能力在业务页面中直显。
- 原位直接编辑、自动保存状态、保存失败回退和可逆操作撤销入口。
- 数据矩阵首次进入时自动创建默认空实例并直接进入编辑区；空结构不显示为已使用。

### 5.2 需要契约或数据变更

- 食材参数：由文本升级为可编辑的结构化食材项。
- 步骤参数：为时长、档位、温度、模式等保留结构化参数。
- 五感记录与问题：补充食谱/步骤来源关联。
- 问题来源：问题点输出与问题管理之间建立稳定的来源、对象和证据关联。
- 素材规模：分页/窗口、过滤契约、封面/缩略图惰性加载。
- 矩阵报告纳入：服务端统一判定对比矩阵和数据矩阵是否存在实质内容；对象、行列或空实例不进入报告，清空后恢复未使用。
- AI 探索：扩展为提案、影响预览、确认执行和审计；删除/覆盖类操作不允许直接执行。
- Hermes 动作：网页、ClawBot、企微共享动作模型、权限校验、风险分级、幂等/回退策略和审计事件。

## 6. 推进节奏

### Wave 0：设计基线与页面审计

- 固化全局组件/导航/状态/媒体/移动端规则。
- 为每个页面标记：复用外壳、交互重构、冻结保护。
- 不改生产前端。

### Wave 1：核心工作流 UI

- 工作台主页、体验计划列表与任务详情。
- 五感、食谱功能、任务级素材和问题管理的连续链路。
- 每个改造切片保留旧业务 API 行为，完成真实前端验证。

### Wave 2：结构化数据与性能

- 食材、步骤、问题来源、五感上下文的数据迁移与 API。
- 大量图片/视频的窗口化和惰性加载。

### Wave 3：AI/Hermes 与消息渠道

- AI 食谱探索提案和确认执行。
- 网页 Hermes、聊天/消息采集共享同一任务—食谱—步骤—问题/素材动作链路。
- 先开放非敏感直接操作；删除、权限、配置、冻结/发布等严格保留确认和审计。

### Wave 4：支撑页统一与体验收口

- 标准管理、报告中心列表、数据分析、AI 助手、设置和认证页。
- 无障碍、加载/错误状态、移动端和性能复核。

## 7. 全局验收标准

- 任一页面能明确识别当前位置、当前任务上下文和主要操作。
- 体验工程师可沿“任务—食谱/步骤—评价—问题点输出—问题整改—报告”完成真实链路，无需复制数据。
- 素材在功能、五感和问题上下文中可见、可预览、可追溯；大量素材不拖慢主页面。
- 任务级素材证据位于主工作区底部全宽区域；左侧目录不再承担图片/视频浏览。
- 食材常态显示为标题下标签，点击后用紧凑浮层修改；不以常驻大表单挤占食谱工作区。
- 任务内的五感、功能、矩阵、问题和报告信息互相可追溯，但不重复维护事实数据。
- 对比矩阵和数据矩阵可试用、可清空、可停用；没有实质内容时，新生成报告不显示对应 Tab，已冻结历史报告保持不变。
- 常规编辑不需要进入独立编辑模式或额外保存；敏感操作有明确确认、影响范围和审计。
- 网页 Hermes 与消息渠道对同一业务对象执行一致的权限和风险策略。
- 冻结报告详情、分享、打印和 PDF 输出的视觉与内容保持不变。
