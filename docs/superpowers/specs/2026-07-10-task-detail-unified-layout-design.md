# 任务详情统一布局与采集协同设计

## 1. 决策与目标

本设计以“体验计划”为任务内的工作组织入口，食谱/功能为主线，现场采集、五感、功能效果、数据矩阵、对比矩阵和报告信息在同一任务上下文中协同。

目标是减少任务页在多个 Tab 间来回切换时的信息断裂，让用户能看见当前食谱、步骤、素材、模块进度与报告状态；不创建第二套数据系统，不重建既有对比矩阵或数据矩阵。

## 2. 不可变边界

- 已冻结报告的详情呈现、报告中心查看、分享页、打印页和 PDF 下载页面均不得改动。
- 本次仅调整任务侧的“报告信息”入口、生成总结和生成报告操作；点击后继续走现有报告查看、冻结与 PDF 链路。
- 对比矩阵和数据矩阵的专业编辑逻辑保留。任务页只显示状态、缺口与入口，不复制矩阵配置或矩阵表格。
- 五感体验是独立模块，不在单一食谱/功能效果评价中混入五感标题、字段或重复表单。

## 3. 统一任务页信息架构

### 3.1 两层导航

1. 平台全局导航：工作台主页、标准管理、体验计划、问题管理、报告中心、数据分析、AI 助手。复用现有全局导航，不在任务页再实现第二套平台导航。
2. 任务内食谱/功能目录：显示本任务食谱/功能、完成状态、步骤进度和素材计数；选择某项后切换当前工作区。

### 3.2 顶部操作与状态卡

任务页顶部统一提供：

- `生成总结`：刷新任务/食谱的结构化总结草稿，承接原总结 Tab。
- `生成报告`：使用已确认内容调用现有报告生成链路，生成独立报告版本。
- 状态卡：五感体验、单一食谱功能、数据矩阵、对比矩阵、报告信息、问题管理。

“报告信息”显示原总结 Tab 的摘要状态、覆盖情况和进入入口；不替代冻结报告详情。

### 3.3 体验计划 / 单一食谱功能工作区

当前食谱工作区由上至下组成：

1. 食谱标题与功能名称。
2. 标题下直接显示食材参数，例如食材名称、克重和单位；不展示“开始前确认基线”或“实际差异补记”等说明性文案。
3. 功能效果评价框：用于录入或确认本功能最终效果、结论和问题；Hermes 可生成草稿，但不得自动覆盖用户确认内容。
4. 功能效果评价关联的图片/视频缩略图直接展示，可预览；不能只显示素材数量。
5. 问题点输出区：体验工程师在功能效果评价中正式输出问题结论；每条问题点显示来源食谱/步骤、关联图片/视频和整改状态，并自动同步到问题管理。问题点输出不是后置的“问题录入按钮”。
6. 动态步骤列表：步骤来自食谱库或任务内配置，可增删、排序；步骤多时，列表区域独立纵向滚动，食谱标题、食材参数、效果评价和问题点输出保持可见。
7. 任务级素材证据区：页面底部常驻，支持当前食谱、未关联、图片、视频、步骤、功能结果等筛选、预览、上传和绑定。

食材参数、步骤、功能效果评价、问题点输出等常规内容采用原位直接编辑和自动保存，不要求先进入编辑模式再点击保存。删除、覆盖或影响多个对象的操作仍需确认。

不保留右侧“关联素材”“功能总览”“本次执行基线”卡片。素材应在功能效果评价内直显，并在任务级素材证据区集中管理。

### 3.4 五感体验工作区

五感体验沿用统一外壳，但中央内容换为五感的标准项、观察记录、结论、问题点输出与关联素材：

- 五感记录独立编辑和确认；不出现食材参数或功能效果评价。
- 当前食谱/步骤仅作为上下文，帮助定位该条五感记录；五感业务数据仍写入既有记录域。
- 对应素材可在记录内直接预览，并与任务级素材证据区保持同源。
- 五感评价确认后产生的问题点，同样作为正式输出同步问题管理，保留感官维度、来源记录、食谱/步骤上下文和关联证据。

### 3.5 问题管理承接

问题管理不承担体验工程师第一次描述问题的职责，而是承接功能效果评价、五感评价和矩阵等编辑页面已经输出的问题点。

- 任务页状态卡显示当前任务的问题数量、整改中数量和待复评数量。
- 食谱/功能目录与步骤项显示各自的问题数量，当前页面保留问题结论、来源和关联证据的摘要。
- 全局问题管理负责跨任务列表、问题等级、责任人、整改方案、复评、关闭和分析。
- 从任务页进入问题管理时，默认带入当前任务、食谱/功能和步骤筛选条件。

### 3.6 矩阵工作区

对比矩阵和数据矩阵保留各自既有版式、用户自定义能力和横向编辑能力。统一布局仅提供状态卡、入口和材料上下文，不在任务计划中复制矩阵编辑器。

## 4. AI 探索功能食谱

食谱/功能目录标题右侧增加极简 `AI 探索` 图标入口，不在任务页展示示例提示词或操作话术。

点击后打开对话式弹窗。AI 读取当前任务、产品、已有食谱、食材、步骤、标准与素材上下文，输出可预览的变更提案。用户确认后才执行变更；未确认的内容不能修改任务。

提案需支持：新增/修改食谱、食材、步骤、排序及相关功能信息。非敏感更新在用户明确表达意图后可直接执行并回显结果；删除或覆盖类变更必须显示影响范围、需要二次确认，并写入审计日志。网页 Hermes、ClawBot 和后续企微渠道复用同一动作契约。

## 5. 数据与接口影响

### 5.1 可直接复用，不要求 API 变更

- 现有食谱、步骤、素材上传/绑定、功能效果评价、报告生成与总结能力可支撑第一轮布局调整。
- 现有素材已能关联任务、食谱和食谱步骤；直接缩略图与预览主要是前端组合和性能优化。
- 顶部“生成总结”“生成报告”可复用现有任务页行为和报告 API。

### 5.2 必须补充的数据/API

以下能力不能仅靠改布局完成：

1. 结构化食材参数：当前 `recipes.ingredients` 为文本。需要设计为结构化食材项（名称、数值、单位、备注），以可靠支持克重编辑、AI 增删食材和报告引用。
2. 结构化步骤参数：当前 `recipe_steps` 仅包含操作、问题与排序。需要为时长、档位、温度、模式等动态参数提供结构化字段。
3. 五感上下文关联：当前 `check_records` 不含 `recipe_id` 或 `recipe_step_id`。需要增加可空关联字段，保证五感记录能追溯到当前食谱/步骤。
4. 问题来源关联：当前问题需要补充食谱和步骤来源关联，以及与“问题点输出”之间的稳定对应关系，避免问题管理无法定位问题来自哪个功能、步骤、五感记录与证据。
5. AI 变更动作：现有 Agent 动作已覆盖食谱创建和步骤创建/更新，但删除类动作被策略拒绝。需要新增受控的食谱更新、食材更新、步骤排序/删除动作；所有高风险动作必须走“提案—确认—执行”流程。
6. 大量素材性能：任务级素材量增长后，需为筛选、分页/窗口化读取和缩略图/视频封面惰性加载补充契约，避免一次性加载所有原始媒体。

## 6. 实施顺序

### Phase A：统一前端外壳与现有能力复用

- 任务页全局导航复用、顶部操作、状态卡、食谱目录与任务级素材证据区。
- 食谱/功能、五感、素材模块按统一布局语言改造，并实现问题点输出与问题状态摘要。
- 报告信息卡与现有总结/报告生成入口接通。
- 冻结报告、打印/PDF、分享页零改动。

### Phase B：上下文与结构化数据

- 数据库迁移、Drizzle schema、API 输入输出和前端类型同步。
- 结构化食材、步骤参数、五感—食谱步骤关联、问题—食谱步骤来源关联。
- 素材窗口化读取与媒体性能优化。

### Phase C：Hermes / AI 探索与消息采集

- 对话式食谱探索提案、影响预览、确认执行与审计。
- 微信/企微等采集渠道接入时，沿用同一任务—食谱—步骤上下文与素材绑定链路。
- Hermes 只做整理、草稿和建议；平台数据库仍是唯一事实源。

## 7. 验收标准

- 用户在任务页无需切换到素材仓库即可查看并绑定当前食谱/功能的关联图片和视频。
- 食谱步骤不被写死；长步骤列表可独立滚动。
- 五感体验、单一功能、数据矩阵、对比矩阵、报告信息均可见其状态并进入原模块。
- 五感页面不出现功能效果评价或食材参数；功能页面不出现五感重复录入字段。
- 功能效果和五感编辑页均可输出问题点；问题管理能追溯到对应任务、食谱/步骤或五感记录，并展示关联证据与整改状态。
- 生成总结与生成报告分别触发现有草稿和报告生成链路。
- 冻结报告详情、报告呈现、分享、打印和 PDF 下载页面视觉与输出不发生改变。
- AI 提案未确认时不写入；确认后变更可审计、可定位任务与对象。
