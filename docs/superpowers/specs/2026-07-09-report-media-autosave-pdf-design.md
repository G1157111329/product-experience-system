# 报告素材预览、实时保存与矩阵 PDF 修复设计

## 目标

在不改变素材存储归属和报告快照语义的前提下，完成以下行为：

1. 报告中心具体报告页中的图片可点击查看原图，视频可点击播放。
2. 功能效果问题点首次编辑时保留全部既有问题点，不再因本地状态未初始化而清空。
3. 任务详情页的普通文本、功能效果问题点和素材选择采用防抖自动保存，并展示保存状态；删除等危险操作仍显式确认。
4. 对比矩阵打印/下载页分别展示“过程记录”和“效果结论”。
5. 将历次报告、矩阵、素材相关修复及禁止回归规则写入 `AGENTS.md`。

## 根因

- 报告详情的新分 Tab 组件直接渲染 `PresignedImage` / `PresignedVideo`，没有把缩略图接入共享预览弹窗。
- 功能效果问题点渲染时会回退到 `recipe.effect_problem_points`，但输入处理函数只读取空的 `effectProblemPoints[recipeId]`，第一次输入会用空数组覆盖既有列表。
- 评价描述已使用 `InlineEditable` 自动保存，但问题点和素材仍依赖手动按钮，状态模型不一致。
- 报告中心“下载”实际打开 `/reports/print`；其中 `PrintInlineMatrix` 只渲染 `conclusion`、`value`，遗漏了已经进入 `ReportDetailMatrixCell.processNotes` 的过程记录。

## 方案

### 报告素材

复用 `ImagePreview` / `MediaThumbnail` 的现有交互和 presign 解析能力，新增一个报告专用、只读的媒体预览小组件。矩阵、功能效果、问题列表和数据矩阵统一使用它。图片预览使用 `object-contain` 原图显示；视频弹窗启用 `controls`、`playsInline` 和 `preload="metadata"`。

### 功能效果状态与保存

把服务器返回的 `effect_problem_points` 合并进本地状态，仅初始化尚不存在的 recipe key，避免刷新覆盖正在编辑的草稿。所有增删改都使用函数式状态更新。

问题点和效果素材变化后，以 recipe 为粒度进行 800ms 防抖 PUT。保存请求携带当前问题点、效果素材和问题点素材的并集。保存期间显示“保存中”，成功显示“已保存”，失败保留草稿并显示“保存失败/重试”。AI 评价前仍强制 flush 当前数据。

### 打印矩阵

`PrintInlineMatrix` 读取 `cell.processNotes`，在 `cell.conclusion` 之前输出“过程记录：”；结论使用独立“效果结论：”标签。两者不得互相回退或覆盖。

### 回归防护

新增纯函数和源代码契约测试，覆盖：

- 未初始化本地问题点时从 recipe 既有列表开始编辑。
- 函数式更新只修改目标问题点。
- 打印矩阵同时消费 `processNotes` 与 `conclusion`。
- 报告素材缩略图具备可点击预览入口。

## 风险控制

- 不修改数据库 schema、素材外键或存储驱动。
- 不改变冻结快照中的原始数据，只修复读取和渲染。
- 自动保存按 recipe 串行/防抖，避免每次按键发请求及旧响应覆盖新草稿。
- 报告只读页不提供编辑或删除入口。
