# 报告内容与素材链路修复设计

## 目标

修复体验报告从录入、冻结快照、报告中心到 PDF 下载之间的字段漂移和素材丢失，同时简化“总结”Tab 的 AI 总结编辑体验。

本次范围包括：

1. 对比矩阵附录图片超过 50 张后仍可完整显示。
2. 对比矩阵冻结报告和 PDF 正确区分“过程记录”与“效果结论”。
3. 功能效果 AI 评价可删除；报告优先采用人工填写的效果评价，人工评价为空时才回退到 AI 评价。
4. AI 总结弹窗改为一个可生成、可编辑、可保存的多行文本框。
5. 报告中心具体报告及其下载 PDF 的问题列表显示关联素材。
6. 已生成的历史冻结报告在不改写历史业务数据的前提下按正确字段渲染。

## 已核验事实

- 生产报告使用 `reports` + `report_snapshots` 分离存储；对比报告的 `reports.content` 可以为空，正式内容来自冻结快照。
- 生产样本快照包含 2 个对比对象、14 个单元格、48 张正文图片和 2 张附录图片。
- 快照单元格同时保存 `process_notes` 与 `effect_summary`。因此历史报告缺少过程记录是读取映射错误，不需要重写快照。
- 素材预签名接口将一次请求截断为前 50 个路径，和“超过 50 张后不显示”的现象一致。
- 本地代码已经具备 AI 评价清空 API 和问题素材聚合的部分实现，但报告中心与 PDF 尚未统一使用相同选择规则。

## 方案比较

### 方案 A：仅修正各页面组件

分别修改报告中心、打印页和分享页中的字段表达式。

优点是改动少；缺点是同一业务规则会复制到多个页面，后续很容易再次出现报告中心与 PDF 不一致。此方案不采用。

### 方案 B：建立共享报告展示规则（采用）

把“字段选择、人工/AI 回退、问题素材合并、预签名分批”整理成可测试的共享函数，各页面只消费统一投影。

该方案能修复现有问题，并让报告中心、打印页和分享页保持一致；改动范围可控，不需要数据库迁移。

### 方案 C：迁移并重写全部历史快照

将旧快照转换成新的字段结构，再让页面只支持新结构。

该方案会改变已经冻结的历史报告，破坏快照不可漂移原则，且回滚风险高。此方案不采用。

## 详细设计

### 1. 对比矩阵字段契约

冻结快照继续保存原始单元格字段，不新增迁移：

- `process_notes`：过程记录。
- `effect_summary`：效果结论。
- `inline_media`：正文媒体。
- `appendix_media`：附录媒体。

报告投影、报告中心和 PDF 必须按上述字段一一映射。任何一个字段为空时显示空态或 `—`，禁止用另一个字段代替。

旧快照中已经存在的 `process_notes` 将直接恢复展示，因此历史报告也能得到修复。

### 2. 超过 50 张素材的加载

保留服务端预签名接口的单批上限，防止一次请求无限放大。共享客户端解析器将去重后的路径按每批最多 50 条切分，并发受控地请求全部批次，最终合并成完整 URL 映射。

报告中心、打印页、分享页和素材 Hook 统一使用该分批逻辑。单个路径失败只影响该素材，并保留可诊断日志，不中断其他批次。

### 3. 功能效果的人工评价优先规则

建立唯一的展示选择函数：

1. `effect_description` 去除首尾空白后非空：采用人工效果评价。
2. 人工效果评价为空且 `effect_ai_result.summary` 非空：采用 AI 评价摘要。
3. 两者都为空：显示空态。

该规则同时用于报告冻结内容、报告中心、分享页和 PDF。

功能效果录入页在已有 AI 评价旁显示删除操作。删除调用现有 DELETE API，同时清空 `effect_ai_result` 和 `effect_score`；成功后刷新当前食谱状态。人工填写的 `effect_description` 不受影响。

### 4. AI 总结单文本框

弹窗只显示一个多行文本框，固定顺序为：

```text
总结：
满意度：
主要优势：
主要风险：
历史表现：
后续建议：
```

“生成 AI 总结”后将现有结构化结果格式化为上述文本。用户可自由修改并保存。

为兼容历史报告和现有报告组件，服务端仍保存结构化 JSON。保存时按固定标签解析文本：

- 标签后的多行内容归入对应字段，直到遇到下一个标签。
- 满意度解析出 0–10 数值；无法解析时保留原值。
- 主要优势、主要风险、后续建议按换行或中文分号转换为数组。
- 如果用户删除全部标签，则把整段内容作为“总结”保存，其他字段保持空值。
- 不再提供独立的“总评标签”输入框；历史 `tag` 仅为兼容显示，不阻碍新总结保存。

### 5. 问题列表素材

共享问题投影按以下来源合并素材并按素材 ID 去重：

1. `materials.issue_id` 直接关联。
2. 五感记录问题通过 `record_id` 关联。
3. 对比矩阵问题通过 `source_cell_id` / `comparison_cell_id` 关联。
4. 功能效果问题通过步骤或效果评价的问题点 `material_ids`、`recipe_step_id`、`recipe_id` 关联。
5. 复评估素材继续归入对应复评估记录。

报告中心问题 Tab 和 PDF 问题列表消费同一 `issues[].materials` 结构。PDF 中每个问题展示有限尺寸的缩略图，但不丢弃素材；大量素材允许自然分页。

### 6. 冻结与兼容原则

- 新报告冻结完整原始字段和素材引用。
- 已冻结报告只修正读取和渲染逻辑，不更新 `report_snapshots.snapshot_json`。
- 报告中心、分享页和 PDF 的优先级规则一致。
- 不新增数据库迁移。

## 错误处理

- 预签名某批失败时继续处理其他批次，并让失败素材使用现有本地 URL 或占位状态。
- AI 评价删除失败时保留现有界面数据并显示错误提示。
- 总结文本解析失败时不丢弃用户内容，整段回退为“总结”字段。
- 问题素材来源不存在时返回空数组，报告主体仍可生成和下载。

## 测试与验收

### 自动化测试

- 预签名路径超过 50 条时会切成多批，并合并全部结果。
- `process_notes` 与 `effect_summary` 分别投影到过程记录和效果结论。
- 人工效果评价优先；为空时回退 AI；两者为空时为空态。
- AI 总结结构化数据与单文本格式双向转换。
- 问题素材从五类来源合并并去重。

### 构建验证

- `pnpm ts-check`
- 相关单元测试
- `pnpm lint`
- `pnpm build`

### 业务验收

- 使用包含超过 50 张图片的对比报告确认报告中心与 PDF 附录完整。
- 使用现有生产样本确认过程记录和效果结论各自显示正确。
- 确认人工效果评价覆盖 AI 评价；清空人工评价后显示 AI 回退；删除 AI 后不再显示。
- 确认总结弹窗只有一个文本框，生成、编辑、保存、再次打开内容一致。
- 确认报告中心问题列表和下载 PDF 均展示问题素材。

## 部署策略

本地验证通过后再部署。生产部署前备份当前运行产物；服务器低内存环境按既有流程准备临时 swap，确认 `.next/BUILD_ID` 与 `dist/server.js` 完整后再切换 PM2。部署后执行登录页、报告详情、问题素材、矩阵附录和 PDF 的最小烟雾验证。
