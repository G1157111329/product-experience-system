# 冻结报告、双矩阵、问题归集与媒体绑定设计

日期：2026-07-15

状态：已确认，等待实施计划
范围：冻结报告详情页、匿名分享页、打印/下载页、任务矩阵入口、素材关联、问题 Tab、功能效果 Tab

## 1. 目标与边界

本次改造交付的是同一份冻结报告在三个阅读表面的一致体验：已登录报告详情、匿名分享页、打印/下载页。报告一旦生成，矩阵内容、字段精度、媒体海报、问题与整改内容均以快照为唯一事实源。

系统必须明确区分两类矩阵，不能使用同一套展示或快照语义：

1. 对比矩阵：`指标 × 对比对象`。左列是项目或细项，每个对象列为完整评价单元格。
2. 数据矩阵：`测试记录 × 过程字段`。每行保留测试序号、规格、食材、耗时、重量、计算指标、效果图、说明和问题点，结构参照 `docs/数据矩阵.pdf`。

本次不改变历史报告的不可变语义，不恢复已废弃的独立“问题输出确认”步骤，不引入第二套任务录入导航。

## 2. 设计原则

- 冻结报告是文档型体验，不使用矩阵内部滚动容器。
- 对比矩阵和数据矩阵分别冻结、分别呈现、分别打印。
- 网页可纵向阅读；矩阵以可阅读列宽直接展开，不以横向滚动替代排版。
- 任意报告包含对比矩阵或数据矩阵时，打印/下载采用 A4 横向。超过一页时自动分页，并重复表头及必要分组字段。
- 视觉沿用平台 Teal 业务色、紧凑表格密度、明确文字层级和稳定 4px 至 8px 间距，不使用营销页式装饰或动效。
- 视频与图片拥有同等级的证据位。视频显示固定比例海报、播放标识与时长，原文件只在打开预览时读取。
- 所有内容在窄屏仍可阅读。移动端不强行显示完整宽矩阵，而是按打印定义分页或按字段分段静态呈现，禁止手势横向滚动作为主阅读路径。

## 3. 冻结快照投影

### 3.1 统一投影

生成报告时建立或扩展一个报告冻结投影，详情、分享、打印/下载均只读取该投影。投影至少包含：

- 报告身份、生成时间、冻结版本和冻结状态。
- `comparisonMatrix`：对象顺序、指标和细项顺序、单元格结论、计算值、问题点和媒体关联。
- `dataMatrix`：列定义、列顺序、显示精度、测试记录排序、分组信息、原始输入、计算值、效果说明、问题点和媒体关联。
- 问题索引：统一问题行头、来源类型、来源详情、整改状态、最新复测和历史复测计数。
- 功能效果：食谱名称、参数、步骤、效果评价、素材和相关问题点。
- 媒体快照：关联素材 ID、名称、类型、显示顺序、图片缩略图或视频海报、视频时长与可控访问引用。

快照中的媒体和数值展示不得在报告生成后跟随实时矩阵、素材重绑或列配置变化而变化。旧报告没有新投影时可使用明确的只读兼容回退，但不可因为任务后来新增矩阵而在旧报告中出现新的矩阵 Tab。

### 3.2 数值与层级规则

- 计算列与输入列共享列定义的 `decimalPlaces`。配置为 0 时输出整数，不得出现默认 5 位小数。
- 冻结报告中的数据矩阵只展示一级大类和二级细项；三级细项不作为新的可编辑层级或单独报告行。已有来源字段可作为二级细项的附加输入文本呈现。
- 数据矩阵问题详情在存在时显示“二级细项 / 三级细项”及其具体输入文本；不存在三级细项时只显示二级细项。

## 4. 素材资产与关联关系

### 4.1 数据模型

素材资产本体可复用，绑定关系不可共享。使用现有 `materials` 与 `material_links` 的多对多语义：

```text
materials (一个文件资产)
  -> material_links (material_id, target_type, target_id, binding_order, metadata)
  -> 目标：矩阵单元格、食谱、食谱步骤、检查记录、问题、整改复测等
```

同一素材允许关联到多个不同目标。唯一约束仅作用于同一 `material_id + target_type + target_id`，保证同一位置不会重复出现同一素材。旧 `materials` 外键列仍保留为历史读回退，报告聚合必须兼容旧字段与新关联表。

### 4.2 用户行为

1. 上传只创建素材资产并进入可选择状态。
2. 用户在任一业务位置选择素材时，新建该位置的关联，而非更新素材本体的唯一归属。
3. 移除素材只解除当前位置关联。其他位置继续保留该素材。
4. 显式“移动素材”操作必须先创建新关联，再确认解除旧关联，避免网络失败造成旧位置假显示或报告缺失。
5. 同一视频重复用于食谱功能、步骤或其他合法位置必须成功，不得返回“所选素材不可用于当前食谱”。
6. 冻结报告复制关联位置所需的媒体展示信息。报告生成后重绑、解绑或删除当前业务位置关联不修改已冻结报告。

## 5. 任务入口状态

任务顶部“对比矩阵”和“数据矩阵”标签以各自的可用状态显示：存在已保存的矩阵内容即显示“已创建”。该状态不依赖生成报告或冻结报告。空壳矩阵、已归档矩阵和未保存草稿不应误显示为已创建。

## 6. 冻结报告的阅读与打印布局

### 6.1 共用结构

报告详情、分享页、打印页复用同一份冻结阅读投影和呈现规则。分享页保持匿名只读。阅读层级如下：

1. 报告身份、冻结状态、产品与体验元信息。
2. 概览与结论。
3. 问题 Tab。
4. 对比矩阵 Tab。
5. 数据矩阵 Tab。
6. 功能效果 Tab。

媒体仅在所属业务对象旁展示，不新增“附录”Tab，也不在报告末尾集中汇总。媒体预览组件必须等待可用的本地、受保护或预签名 URL，不得将原始对象 key 当作相对 URL 请求。`data:` 占位图不得触发网络请求。

### 6.2 对比矩阵

- 采用“项目、对象 A、对象 B... ”的横向表格，多个对象列尽量等宽。
- 对象单元格可包含描述、评分、计算结果、问题点、图片或视频海报。
- 视频与图片占用相同尺寸和比例的预览位。
- 对比矩阵分组小结必须在详情、分享和打印页全部保留。

### 6.3 数据矩阵

数据矩阵按实验记录表展示，列由冻结列定义确定。典型列包括：序号、口径规格、产品图、食物、耗时、食物重量、出汁重量、果渣重量、果汁净重量、果汁内渣重量、出汁率、纯汁率、含渣率、效果图、效果说明、问题点。

- 同一测试序号下不同规格记录成组，组使用克制的浅色交替区分。
- 计算指标使用等宽数字和字段级精度。
- 连续图片和视频海报按同一“效果图”字段排列。
- 数据矩阵完整静态展开，不允许内部横向滚动。
- 打印时使用 `@page` 横向规则和分页控制，跨页重复表头、序号、规格或食材等保证上下文所需字段。

## 7. 问题 Tab

问题 Tab 是所有来源问题的统一索引，默认每行折叠。列表固定呈现四个字段：

| 字段 | 规则 |
| --- | --- |
| 问题等级 | 语义等级标签，不只使用颜色表达。 |
| 问题类型 | 五感体验、食谱/功能、食谱/功能-对比矩阵、数据矩阵。 |
| 问题点描述 | 可读的来源化描述。单一食谱功能使用“XX 食谱/功能效果不合格”。 |
| 整改状态 | 未整改、整改中、已整改等状态标签。 |

点击问题行后展开来源字段、素材和整改信息。再次点击收起。整改复测数量大于等于 2 时，默认仅显示最新一条，并增加“整改复测记录数：N”二级折叠入口。

### 7.1 单一食谱/功能问题

- 食谱名称。
- 食谱配方 / 参数。
- 食谱步骤：默认折叠，仅显示“食谱步骤：N 步”；步骤数为 0 时不显示该行。展开后显示步骤详情、步骤问题点和证据素材。
- 食谱效果评价及关联素材。
- 已整改时显示整改效果评价和整改素材。

不单独输出一个重复的“问题”行标签。问题点描述已经在统一行头表达。

### 7.2 对比矩阵问题

- 对象。
- 项目。
- 细项。
- 问题。
- 素材。
- 已整改时显示整改效果评价与整改素材。
- 复测数大于等于 2 时显示最新记录和历史计数入口。

### 7.3 数据矩阵问题

- 一级大类。
- 二级细项 / 三级细项：展示实际二级或三级输入文本，三级不存在时不补空值。
- 对比维度。
- 问题。
- 素材。
- 已整改时显示整改效果评价与整改素材。
- 复测数大于等于 2 时显示最新记录和历史计数入口。

### 7.4 五感体验问题

- 问题描述。
- 非标准问题仅显示“描述检查项内容”和检查结果。
- 标准问题显示检验标准类型、检验要求及范围、检查标准、检查结果和原位证据素材。
- 检验要求及范围映射：通用标准使用触点，品类标准使用具体检查条目，感官评价使用感官评价准备。
- 检查标准映射：通用标准使用体验标准，品类标准使用检查标准，感官评价使用主观满意度评分说明。
- 已整改时显示整改效果评价与整改素材；多次复测遵循统一的最新记录和历史计数规则。

## 8. 功能效果 Tab

保留功能效果清单的效果预览卡片，但下方使用单食谱列表式展开，详情、分享、打印/下载一致：

1. 食谱名称，带步骤数、效果评分、问题点数量小标签。
2. 食谱 / 食材。
3. 效果评价与证据素材。
4. 食谱步骤，默认折叠为“食谱步骤：N 步”；展开后显示步骤详情、步骤问题点与证据素材。
5. 食谱效果评价及其素材。

下载页不得将步骤、步骤问题证据、效果问题点和功能效果素材拆成彼此脱离的分割视图。

## 9. 验收标准

所有开发队列完成后只进行一次本地 Docker 全局部署验证。期间仅执行静态检查和对应的测试，不反复重建容器。

1. 同一视频绑定到两个食谱位置和一个矩阵位置均成功。解除其中一个位置关联不影响其他位置和已冻结报告。
2. 绑定失败或移动中断不会产生“UI 已绑定、报告未绑定”的状态。
3. 0 位小数的数据列和计算列在详情、分享和打印中均不出现小数；其他精度严格匹配冻结列配置。
4. 三级细项不可再作为数据矩阵新增层级；已有来源字段在问题详情按规则呈现。
5. 创建且保存有效对比矩阵或数据矩阵后，任务顶部立即显示已创建，不依赖报告生成。
6. 冻结后，对比矩阵和数据矩阵各自可读、无内部滚动、计算值与分组小结完整存在。
7. 视频在详情、分享和打印中有稳定海报预览，不会表现为失效素材。
8. 打印/下载含矩阵时为 A4 横向，跨页表头和必要分组字段重复，媒体、计算列和大类小结均在原业务位置保留，不追加末尾附录。
9. 问题 Tab 统一显示四列行头，默认折叠。四类来源展开字段、素材、整改最新记录和历史计数均准确。
10. 功能效果 Tab 和下载页以单食谱列表式展开，不重复“问题”行，也不使用分割式步骤视图。
11. 全局验证顺序：聚焦单元/契约测试、类型检查、Lint、生产构建、Docker 启动、浏览器验收详情页/分享页/打印页及任务矩阵入口。

## 10. 非目标

- 不重新设计全局导航或恢复已删除的任务内第二套目录。
- 不改变旧报告冻结内容。
- 不把素材资产改为全局单一归属。
- 不用仅 API 成功的冒烟测试替代浏览器可见验收。
