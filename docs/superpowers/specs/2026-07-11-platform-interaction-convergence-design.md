# 全平台交互一致性与核心链路收口设计

日期：2026-07-11
状态：已确认
实施策略：核心链路优先，同时收口全局交互底座

## 1. 决策

平台不进行推翻式改版。保留 Golden Yellow 品牌、全局侧栏/移动导航、现有业务模块和已经成熟的数据矩阵录入能力，在此基础上消除页面各自实现造成的布局漂移、状态语义不一致、重复入口和额外确认。

优先工作链：

```text
体验计划 → 食谱/功能、五感、矩阵、素材 → 问题闭环 → 冻结报告 → 匿名分享 / 打印 PDF
```

核心链路稳定后，再将同一页面外壳、交互状态和响应式规则扩展到工作台、标准管理、报告列表、数据分析和全局 AI 助手。

本设计覆盖并纠正以下旧规格边界：

- 冻结报告不再视为完全禁止调整的视觉保护区。报告内容仍保持冻结，但数据矩阵 Tab、冻结锚点、匿名分享一致性和数据矩阵阅读版式必须修正。
- 报告详情与匿名分享保持相同内容结构；打印/PDF共享冻结内容和显示门禁，但采用独立纸张版式。
- “食谱问题自动同步，无二次确认”不等于移除问题输出。页面必须保留只读的“问题管理输出”反馈区。
- 体验计划不再保留内嵌 AI 方案/AI 助手 Tab；全局 AI 助手仍是独立模块。

## 2. 体验原则

### 2.1 任务上下文优先

用户进入页面后应立即知道：当前任务或对象是什么、当前状态是什么、下一步可做什么、刚才的输入是否已保存。页面标题、状态、主动作和模块切换保持稳定位置，不让大面积说明文字占据首屏。

### 2.2 原位编辑，离开即保存

- 文本、数值、问题点、食材和步骤参数使用本地草稿。
- `blur` 或 `Enter` 提交，`Esc` 恢复本次未提交值。
- Popover、Dialog 或当前编辑对象关闭前必须 flush 最后草稿，不能因清除 timer 丢失输入。
- 保存只更新当前字段或当前记录，不切换整页 loading，不抢焦点，不折叠工作区。
- 保存中使用紧邻字段的轻量状态；成功状态短暂显示后淡出；失败保留草稿并提供重试。
- 同一交互在全平台使用同一提交手势和状态用词。

### 2.3 状态必须可信

- 任务、问题、报告状态由统一机器状态映射生成，不允许页面自行翻译同一状态。
- “草稿”不得在组件层伪装成“已完成”。
- 状态使用文字、图标和语义色共同表达，不能只靠颜色。
- 加载、空数据和加载失败是三种状态，不允许把尚未加载或请求失败显示成“暂无数据”。

### 2.4 动效服务反馈

- hover、focus、展开、保存成功、错误和弹窗使用 150–250ms 状态过渡。
- 不使用页面入场编舞、弹跳或装饰动画。
- 新增记录后可对新增项做一次短暂背景强调；保存成功使用轻量淡入淡出，不移动布局。
- 所有动效支持 `prefers-reduced-motion`。

## 3. 全局页面与组件规范

### 3.1 页面骨架

所有认证页面使用统一顺序：

1. `PageHeader`：标题、必要上下文、一个主动作和次级操作。
2. 状态或指标摘要：只有帮助判断和行动的数据进入首屏。
3. `FilterBar` 或模块切换：筛选和导航不混用。
4. 主工作区。
5. 辅助信息、素材或历史记录。

列表、详情和分析页不得各自重新定义标题尺寸、左右边距、加载态和移动端底部安全区。问题详情、AI 助手和分享阅读容器需要接入同一结构规范，但匿名分享不显示平台导航。

### 3.2 控件密度

- 移动端高频点击目标不小于 44×44px。
- 桌面端正文按钮默认高度 36–40px；仅低频工具栏图标允许 32px，但必须有 tooltip、focus ring 和可访问名称。
- 不再使用 24–28px 的现场操作按钮。
- 正文和表单最小 14px；辅助信息通常不小于 12px；10–11px 仅保留给非关键短标记，不能承担状态或操作说明。
- 删除采用低强调 ghost 图标或“更多”菜单；真正执行删除时再使用破坏性确认。

### 3.3 Tab 与模块切换

- 页面内容 Tab 使用语义化 `tablist/tab/tabpanel`，支持方向键、Tab、Enter/Space和 `aria-selected`。
- 当前任务模块切换和报告内容 Tab 使用不同组件语义，不互相伪装。
- 移动端任务模块使用可换行的紧凑模块按钮或两列网格，不采用横向拖动条。
- 当前项始终有文字和状态，不用只有颜色的选中边框。

### 3.4 表单、搜索和反馈

- 输入必须有关联 label；图标按钮必须有 `aria-label`。
- 搜索使用 250–350ms debounce，并取消或忽略过期请求；输入期间保留现有结果，不反复闪回整页骨架。
- loading 使用与内容形状匹配的 skeleton；局部保存使用 inline status；长操作显示明确阶段和取消/重试策略。
- Toast只通知跨区结果，字段级错误必须紧邻字段显示。

### 3.5 动作层级

- 每个页面或当前工作区最多一个视觉主动作。
- 同组次要操作使用 outline/ghost；低频动作进入更多菜单。
- 按钮名称使用“动词 + 对象”，避免“确定”“操作”“处理”等含糊用词。

## 4. 体验计划录入

### 4.1 顶部任务区

- 任务默认进入“功能/食谱”，不再默认进入隐藏的 `agent` Tab。
- 移除任务页 `agent` 状态、`?tab=agent` 深链和 `AgentPresetPanel/AgentAssistPanel` 内容分支。
- 桌面端保留任务名称、状态、必要元数据、生成总结和生成报告。
- 移动端首屏压缩任务元数据：标题和状态常显，型号/阶段等次级信息可展开；“生成报告”为主动作，“生成总结”为次动作，“转移”等低频操作进入更多菜单。
- 五感、功能/食谱、数据矩阵、对比矩阵、报告信息使用紧凑模块切换，不恢复第二套“录入目录”，不加入问题管理卡。

### 4.2 功能/食谱

- 左侧或上方食谱列表使用真正的 button/listbox 语义，支持键盘选择。
- 选中食谱标题下直接显示摘要标签：食谱显示食材名称、克重、单位和 `+N`；功能显示“功能”类型及已有功能参数摘要。没有结构化参数时只显示类型，不编造内容。
- 食材标签点击后打开紧凑编辑浮层；关闭浮层前提交最后一次编辑。
- 步骤多时仅步骤列表纵向滚动，标题、摘要和当前效果状态不随步骤消失。
- 功能效果评价保留描述、素材、AI评价结果和问题点，但减少嵌套卡片，不把每个字段都包成独立卡片。

### 4.3 问题管理输出

功能/食谱底部必须呈现只读的“问题管理输出”：

- 步骤问题和效果问题保存后自动同步，不增加“登记为问题”或“确认输出”按钮。
- 显示问题点、可选问题详情、来源步骤/效果、附录素材、等级、整改状态。
- 同步期间显示“同步中”；成功后显示“已进入问题管理”；失败保留问题草稿并提供重试。
- 点击问题可进入全局问题详情，但当前任务页仍保留来源和状态摘要。

### 4.4 五感与素材

- 五感沿用相同页面外壳和保存反馈，但保留独立字段，不混入食材或功能效果标题。
- 底部保留唯一“素材证据”区；数据矩阵和其他模块不重复建立素材池。
- 添加素材使用一个主入口和紧凑来源菜单；上传区支持粘贴，文本输入聚焦时不拦截粘贴事件。
- 素材缩略图直接显示归属、类型和状态；编辑图片不改变原有关联。

### 4.5 矩阵录入

- 数据矩阵继续使用桌面表格、移动卡片的双呈现，不退回把宽表压进手机。
- 数值、文本和问题点统一支持 `blur/Enter` 提交。
- 列顺序保持：层级 → 主素材 → 对比/输入 → 计算 → 效果素材 → 效果评价 → 问题点。
- 对比矩阵移动端改为“当前对比项 + 对象切换/并排摘要”的聚焦录入，不要求用户在 720px 以上宽表中反复横向拖动。
- 删除对象、类目、细项和矩阵使用低强调入口，但清空或停用仍显示影响范围并确认。

## 5. 冻结报告、分享与打印

### 5.1 冻结锚点

- 报告所有读取面优先按 `reports.snapshot_id` 精确读取 `report_snapshots.id`。
- 只有历史报告没有 `snapshot_id` 时，才允许回退到该报告最高版本快照，并记录兼容路径。
- `snapshot_id` 已存在但目标快照缺失时必须返回完整性错误，不得静默改读其他版本。
- 详情、匿名分享、打印/PDF不得自行选择不同快照。

### 5.2 统一冻结阅读模型

服务端建立单一 `FrozenReportViewModel`，统一提供：

- 标题、型号、阶段、状态、冻结时间和版本。
- 总结、问题、功能效果。
- 数据矩阵或对比矩阵的冻结投影。
- 问题附录素材、整改素材和复评素材。
- 各章节的 meaningful-content 可见性。

详情与匿名分享消费相同阅读模型和相同章节组件。分享页只移除平台导航、编辑和内部管理动作，不隐藏问题、整改、功能效果，也不用功能瀑布冒充矩阵。

### 5.3 独立矩阵 Tab

- 普通报告显示“数据矩阵”。
- 对比报告显示“对比矩阵”。
- 只有冻结投影存在实质值、结论、素材、叙述或问题时才显示相应 Tab。
- 空结构、空对象、空行列和仅创建实例不触发 Tab。
- 前端兼容旧 `matrix` key，但新合同输出明确的 `data_matrix` 或 `comparison_matrix`。

### 5.4 数据矩阵阅读版式

- 冻结数据矩阵不复用录入宽表。
- 每条记录先显示一级/二级/三级路径，再以响应式字段网格显示有效输入、计算结果、效果评价、问题点和素材。
- 空字段不占据固定列宽；媒体直接显示缩略图。
- 不提供编辑、拖动、列宽调整或横向拖动条。
- 对比矩阵可保留对照表语义，但移动端使用对象分段或逐项对比，不隐藏必要上下文。

### 5.5 打印/PDF

- 打印/PDF与详情/分享共享冻结快照和内容显示门禁；`PrintReportViewModel` 只能由 `FrozenReportViewModel` 投影产生，不得再次读取或重组另一份业务事实。
- 不使用网页 Tab；章节按总结、问题、矩阵、功能效果连续排版。
- 使用 A4分页、页眉页脚、媒体尺寸限制和可预测的断页规则。
- 矩阵转换为可跨页的分组表或记录块，不横向裁切；必要时对比矩阵使用横向纸张，而不是缩小到不可读。
- 打印视觉统一到当前品牌 token 的打印变量，不要求与网页卡片结构一致。

## 6. 问题、工作台及支撑页面

### 6.1 问题管理

- 问题列表和详情使用同一状态字典和展示组件。
- 问题行与展开控件使用语义 button，禁止 button 嵌套 button。
- 详情保存具有 pending、防重复提交、错误反馈和草稿保留。
- 从任务、食谱、五感或矩阵进入时自动带入来源筛选和上下文。

### 6.2 工作台

- 保留指标与最近任务/问题的稳定双栏结构。
- 删除重复的审核入口；首屏优先继续任务、待处理问题和待生成报告。
- 标签字号和行距提升到统一可读下限，保持专业密度但不依赖微型文字。

### 6.3 标准管理、任务列表与报告列表

- 统一搜索 debounce、过期请求取消、加载和错误状态。
- 列表主行使用 `EntityListItem` 或同等键盘语义。
- 报告列表显示真实状态；选择框扩大整行热区并提供报告名称。

### 6.4 数据分析

- 指标卡和图表保留现有数据，不扩大装饰面积。
- 移动端四列明细改为两列或逐行指标，不允许文字被压成窄列堆叠。
- 筛选、空态、错误态与其他列表页一致。

### 6.5 全局 AI 助手

- AI 助手保留为全局独立模块，不嵌入体验计划录入页。
- “对话/平台操作”使用语义 Tab 并表达当前模式。
- 移动端高度统一扣除顶部、底部导航和 safe-area，避免输入框被遮挡或产生双重滚动。
- Hermes的全平台动作能力继续使用统一权限、确认、审计和幂等契约；删除、权限、冻结、发布和外发等敏感动作必须确认。

## 7. 实施顺序

### Wave 1A：报告合同与冻结可信度

- 快照按 `snapshot_id` 锚定。
- 详情/分享统一冻结阅读模型。
- 独立数据矩阵/对比矩阵 Tab和 meaningful-content 门禁。
- 数据矩阵只读无横向滚动版式。
- 打印/PDF维持独立纸张布局并共享内容门禁。

### Wave 1B：任务录入收口

- 移除任务内 AI 入口并默认进入功能/食谱。
- 恢复食材/功能摘要标签和问题管理输出。
- 修复食材关闭丢稿、数值 Enter 保存、触控尺寸和键盘操作。
- 压缩移动任务首屏；优化对比矩阵移动录入。

### Wave 1C：问题闭环

- 统一状态字典、列表/详情结构、保存反馈和来源上下文。
- 校验任务、问题、报告三处问题数量、文本和素材一致。

### Wave 2：共享底座与支撑页

- 统一 PageShell、Header、Tab、SaveStatus、Loading/Error/Empty、按钮尺寸和表单标签。
- 覆盖工作台、标准、任务/报告列表、分析和全局 AI 助手。

### Wave 3：动态反馈、可访问性与性能复核

- 状态动效、减少动态效果、键盘链路、对比度和触控目标。
- 搜索竞态、媒体惰性加载、复杂矩阵渲染和页面性能。
- 清理废弃任务详情组件，建立真实运行路径清单，防止修改未接入组件。

## 8. 验收标准

- 任务默认进入功能/食谱，不存在任务内 AI 助手入口或 `tab=agent` 可达内容。
- 移动端进入任务后无需先滚过大面积元数据和状态卡才能开始录入。
- 食谱与功能标题下均有真实摘要标签；关闭食材浮层不丢最后输入。
- 问题保存后自动进入问题管理，底部直接显示同步状态和问题闭环，无二次确认按钮。
- 文本、数值和问题点均可通过失焦或 Enter 保存，保存不抢焦点、不切换整页 loading。
- 任务底部只有一个素材证据区；粘贴、上传、预览和图片编辑可在真实浏览器完成。
- 普通冻结报告只在有实质内容时显示“数据矩阵”；对比报告显示“对比矩阵”。
- 数据矩阵详情和匿名分享无编辑能力、无横向拖动条，且均读取报告锚定快照。
- 详情与匿名分享的章节、问题、矩阵、功能效果和素材一致；匿名分享无需登录。
- 打印/PDF内容与冻结阅读模型一致，但采用独立纸张排版，无网页导航、Tab或交互控件。
- 问题列表、详情和报告使用同一状态词；草稿不显示成已完成。
- 所有移动端高频目标至少 44×44px；关键文字不使用 10–11px。
- 390、768、1024、1440宽度无非必要页面级横向滚动或文字重叠。
- 键盘可完成导航、Tab切换、食谱选择、展开、编辑和提交；图标按钮均有可访问名称。
- 浏览器控制台无新增错误，关键 API 无失败请求；`pnpm ts-check`、`pnpm lint`、相关契约测试、生产构建和 Docker真实链路回放全部通过。

## 9. 非目标

- 不重建 Hermes Runtime 或模型层。
- 不引入第二套食谱、问题、素材或报告事实数据。
- 不改变已经冻结报告的内容，只修正其锚点、缺失章节和阅读呈现。
- 不用大面积动画、渐变、玻璃拟态或装饰卡片提升“视觉感”。
- 不在一次提交中同时重写全部页面；每个 Wave 必须可验证、可回滚并保持主流程可用。
