# 产品体验管理平台 PRD 补充说明：录入链路、报告输出与 AI Agent

日期：2026-05-23  
适用版本：UI 重构 Phase 1 之后的增量版本  
面向对象：产品、体验工程师、前端/后端开发、AI Prompt 配置维护人员

## 1. 背景

UI 重构 Phase 1 已完成共享组件抽取和基础页面重构。后续迭代重点从“页面结构统一”转向“体验工程师实际录入效率”和“报告评审/输出质量”。

本补充文档记录 Phase 1 之后的主要更新，方便后续开发者理解当前产品逻辑、页面入口、AI Agent 运行方式和后续维护边界。

## 2. 核心目标

1. 让体验工程师在任务详情页完成“素材整理、五感记录、功能/食谱、AI总结、报告生成”的连续录入。
2. 减少 Excel 式手工整理成本，把手机拍摄的图片/视频作为证据素材内置管理。
3. 让 AI 以两种方式辅助：
   - AI体验方案：在录入前预设检查项和功能/食谱草稿。
   - AI辅助：在录入过程中以聊天方式回答疑问。
4. 优化报告中心、报告详情、打印/PDF导出、分享页的阅读层级和媒体展示。
5. 统一平台设置入口，避免设置分散在导航、个人信息和 AI 配置多个位置。

## 3. 主要更新总览

| 模块 | 更新方向 | 说明 |
| --- | --- | --- |
| 任务详情页 | 报告录入链路重构 | 从 Tab 式页面调整为“录入目录 + 内容区 + 可选 AI辅助”的工作台结构 |
| 素材证据 | 素材优先录入 | 图片/视频证据前置，支持绑定到五感记录、功能步骤、效果评价 |
| AI体验方案 | 页面内工作区 | 从顶部按钮/弹窗改为左侧目录第一项，提供五感和食谱功能两块 AI 预设 |
| AI辅助 | 实时聊天 | 从“完整度/建议卡片”改为可唤醒聊天面板 |
| 功能/食谱 | 首次加载修复 | 已有食谱/功能进入页面即可显示，不再依赖新增弹窗触发刷新 |
| 报告中心 | 报告展示优化 | 修复原始 JSON 展示、媒体过小、报告详情层级不清等问题 |
| 打印/PDF | 排版优化 | 清理底色和信息层级，素材仍保持与对应结论同区展示 |
| 设置 | 统一入口 | 品类产品、通用标准、AI模型、Prompt模板统一从“平台设置”进入 |

## 4. 任务详情页录入链路

### 4.1 当前页面结构

任务详情页现在以 `ReportAuthoringShell` 为主容器：

左侧为录入目录：

1. AI体验方案
2. 五感体验
3. 功能效果
4. AI总结/报告

中间为当前录入区：

- AI体验方案：生成和预设检查项/食谱功能。
- 五感体验：维护检查记录和问题点。
- 功能效果：维护功能/食谱、步骤、效果/出品评价。
- AI总结/报告：生成或编辑 AI 总结，生成报告。

右侧为可选的 AI辅助聊天栏：

- 默认不占位。
- 点击左侧目录右上角 `AI辅助` 按钮后唤醒。
- 在超宽屏作为第三栏展示；在普通桌面宽度下会下沉，避免挤压中间录入区。

### 4.2 素材证据栏

素材证据栏只在五感体验和功能效果页面出现。

作用：

- 统一展示当前任务下图片/视频。
- 支持拍照、录像、相册图片、相册视频上传。
- 支持按全部、未关联、已关联、图片、视频、五感、步骤、效果筛选。
- 选择素材后绑定到当前选中的五感记录、功能步骤或效果评价。

设计原则：

- 素材证据是体验工程师从手机拍摄资料到报告证据的中转区。
- 不再在目录中保留独立“素材证据”入口，避免录入路径割裂。
- 素材栏按钮在中等桌面宽度下换行，避免标题和说明被挤成竖排。

相关文件：

- `src/app/(main)/tasks/[id]/components/material-evidence-rail.tsx`
- `src/app/(main)/tasks/[id]/page.tsx`

## 5. AI体验方案

### 5.1 入口变化

原来：任务详情页顶部按钮 `AI体验方案`，点击后打开弹窗。  
现在：左侧录入目录第一项 `AI体验方案`，点击后进入专属工作区。

这样做的原因：

- AI体验方案属于“录入前预设/规划”，不是一个临时操作按钮。
- 用户需要先看 AI 推荐内容，再决定删减和写入草稿。
- 页面内展示比弹窗更适合预览检查项、食谱、步骤和推荐原因。

### 5.2 AI五感体验

位置：AI体验方案页面左侧信息窗。

交互：

1. 点击 `AI五感体验`。
2. 运行 `senses_standard_preset` Skill Prompt。
3. 输出建议重点检查指标。
4. 用户可删除不需要的条目。
5. 点击 `快速预设` 后写入五感体验草稿。

输出内容：

- 检查指标/重点项
- 标准类型或分类
- 推荐原因

写入后：

- 创建 `check_records` 草稿记录。
- 检查结果、问题描述、素材保持空白，由体验工程师现场录入。

### 5.3 食谱功能AI探索

位置：AI体验方案页面右侧信息窗。

交互：

1. 点击 `食谱功能AI探索`。
2. 运行 `recipe_scene_preset` Skill Prompt。
3. 输出功能名称/食谱、食材/参数、推荐原因。
4. 点击条目可展开步骤预览。
5. 用户可删除不需要的条目。
6. 点击 `快速预设` 后写入食谱名称、食材/参数和步骤。

输出内容：

- 功能名称或食谱名称
- 类型
- 食材/参数
- 推荐原因
- 步骤预览

写入后：

- 创建 `recipes` 记录。
- 创建对应 `recipe_steps`。
- 问题点、效果评价、素材由体验工程师后续补充。

相关文件：

- `src/app/(main)/tasks/[id]/components/agent-preset-panel.tsx`
- `src/app/api/tasks/[id]/agent-presets/route.ts`
- `src/lib/agent-skills.ts`
- `src/lib/server/agent-skills.ts`

## 6. AI辅助聊天

### 6.1 入口

左侧录入目录标题右侧有 `AI辅助` 按钮。

交互：

- 点击后展开 AI 辅助聊天栏。
- 再次点击或点关闭图标可收起。
- AI辅助不再展示“输入完整度”“建议确认”等固定评分内容。

### 6.2 能力定位

AI辅助用于体验工程师实时提问，例如：

- 当前任务应该注意哪些体验点？
- 某个素材应该绑定到哪里？
- 某条五感记录怎么写更清楚？
- 功能效果评价怎么组织语言？
- 报告总结有没有风险遗漏？

AI会读取任务上下文，包括：

- 任务基础信息
- 五感记录
- 功能/食谱
- 素材数量
- AI总结

相关文件：

- `src/app/(main)/tasks/[id]/components/agent-assist-panel.tsx`
- `src/app/api/tasks/[id]/agent-chat/route.ts`

## 7. 功能效果录入

### 7.1 页面结构

功能效果页面现在使用 `FunctionsInputWorkspace`：

- 左侧：功能/食谱列表。
- 右侧：选中功能/食谱详情、步骤时间线、效果/出品评价编辑区。

功能/食谱列表显示：

- 名称
- 步骤数量
- 是否有评价
- 问题点数量
- AI评分

### 7.2 效果/出品评价

每个功能/食谱都有独立的效果评价区：

- 评价描述
- 效果素材
- AI总结评分
- 问题点列表
- 问题点素材绑定

保存时写入：

- `effect_description`
- `effect_problem_point`
- `effect_material_ids`

### 7.3 首次加载修复

历史问题：

- 已有功能/食谱首次进入功能效果页面时可能不显示。
- 点击“新增功能/食谱”再关闭弹窗后列表才刷新出来。

修复策略：

1. 父页面已加载的 `reportRecipes` 作为 `FunctionsTab` 初始数据。
2. 切换到功能效果 Tab 时主动刷新食谱缓存。
3. `FunctionsTab` 挂载后后台刷新最新数据。
4. 单个素材请求失败不再中断整批食谱加载。
5. 工作区增加 loading 骨架、空态和手动刷新按钮。

相关文件：

- `src/app/(main)/tasks/[id]/components/functions-input-workspace.tsx`
- `src/app/(main)/tasks/[id]/page.tsx`

报告中心当前定位不是“独立评审流”，而是在线报告工作流的一部分。

已调整：

- 移除报告中心不必要的“报告评审编辑栏”倾向。

## 13. 后续接手注意点

### 13.1 不要把 AI体验方案再改回弹窗

AI体验方案现在是录入目录中的独立步骤。它承担“录入前预设”的职责，应保留页面内预览、删减、快速预设的交互。

### 13.2 不要把 AI辅助做成固定占位

AI辅助是可唤醒聊天，不应默认占据大面积空间。普通桌面宽度下应避免三栏硬挤，超宽屏才适合并排三栏。

### 13.3 素材证据应靠近录入区

素材证据栏是体验工程师从手机素材到报告证据的桥梁。它应在五感体验和功能效果页面前置出现，不建议放到独立 Tab 中。

### 13.4 报告输出必须保持“结论与素材同区”

打印/PDF和报告详情中，素材证据应跟对应检查记录、问题点、步骤或效果评价放在一起。不要把所有素材统一放到最后附录，否则会回到 Excel 手动找图的问题。

### 13.5 功能/食谱列表要兼顾缓存和刷新

功能效果页依赖异步加载食谱、步骤、素材。后续改动时应保留：

- 父级 `reportRecipes` 初始数据。
- Tab 进入时主动刷新。
- 子组件手动刷新。
- 单个素材加载失败不影响主列表。

### 13.6 Prompt 模板是版本化配置

编辑 Prompt 不覆盖历史版本，而是创建新版本并启用。后续若做回滚/审计，可以基于 `agent_skill_versions` 和审计日志扩展。

## 14. 建议后续迭代

1. 增加 AI体验方案运行结果的本地缓存，避免切走页面后结果丢失。
2. 增加 Prompt 模板预览运行能力，管理员可在设置页用当前任务模拟输出。
3. 给功能/食谱列表增加搜索和折叠分组，适合项目后期食谱数量较多的场景。
4. 给报告打印页增加“紧凑/详细”输出模式。
5. 为素材证据增加批量重命名或按拍摄时间分组。
6. 为 AI辅助增加引用当前选中记录/步骤/素材的上下文提示。
